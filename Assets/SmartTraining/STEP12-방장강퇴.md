# 방장 참가자 강퇴

현재 방장이 같은 방에 접속 중인 참가자를 강퇴할 수 있습니다.
강퇴된 참가자는 로그인과 로비 접속을 유지한 채 방 화면에서 로비 화면으로 돌아갑니다.

## 확인 순서
1. ASP.NET과 Unity Play를 종료한 후 ASP.NET을 다시 빌드·실행합니다.
2. Unity ApiLobby 씬과 `Builds/Client/Smart Training Client.exe`를 서로 다른 닉네임으로 같은 방에 접속시킵니다.
3. 방장 화면에서 대상 닉네임의 `강퇴` 버튼을 누릅니다.
4. 대상 화면에 `방장에 의해 강퇴되었습니다. 로비로 돌아왔습니다.`가 표시되는지 확인합니다.
5. 방장 화면에서는 해당 플레이어가 사라지고 방 목록의 접속 인원이 줄어듭니다. 방장의 연결과 방장 권한은 유지됩니다.
6. 강퇴된 참가자가 같은 방에 다시 참가해 봅니다. 새 접속 예약으로 입장할 수 있고 기존 방장은 유지됩니다.
7. 다른 참가자에게 방장을 위임하면 새 방장에게 강퇴 버튼이 나타나고 이전 방장은 강퇴 권한을 잃습니다.

버튼 클릭으로 강퇴 요청을 전달합니다. 현재 동작은 해당 방 접속을 종료하며, 이후 재입장은 허용합니다.
대상이 이미 나갔거나 방장이 바뀌었으면 서버 오류 메시지를 표시합니다.
전용 서버가 실제 연결을 종료할 때까지 방 슬롯을 유지하므로, 전송 실패 때문에 접속 인원 정보만 먼저 없어지지 않습니다.
강퇴 완료 표시도 해당 플레이어가 사라진 뒤에 보여줍니다.

## 권한과 접속 보호
- 요청자의 ID는 로그인 토큰에서 확인합니다. 현재 방장만 강퇴할 수 있습니다.
- 자기 자신, 입장 예약자, 다른 방 사용자, 없는 사용자는 대상이 될 수 없습니다.
- 서버 간 강퇴 명령에는 대상의 현재 입장 토큰을 포함합니다. 늦게 도착한 이전 명령이 재입장한 새 접속을 끊지 않습니다.
- 기존 방 퇴장 정리와 방장 자동 위임을 계속 사용합니다.

## 함수별 변경
- ASP.NET `RoomController.KickRoomUser`: `POST /api/Room/kick` 인증 요청 처리.
- ASP.NET `RoomService.KickRoomUserAsync`: 방장 권한·대상 검사 후 등록된 전용 서버에 `KickUser` 전달.
- Unity `RoomHubConnection.Tick`, `RoomDedicatedServer.KickUser`: 정확한 사용자·입장 토큰에 해당하는 접속만 종료하고 강퇴 사유 전달.
- Unity `RoomNetworkClient.OnDisconnected`: 서버가 보낸 접속 종료 사유 저장.
- Unity `TrainingApiClient.KickRoomUser`, `ApiLobbyScreen.KickRoomUser`: 방장 버튼과 요청 완료 확인.
- Unity `ApiLobbyScreen.Update`, 기존 `LeaveRoom`: 종료 사유 표시와 로비 화면 복귀.

요청 예: `{ "lobbyId": "로비 ID", "roomId": "방 ID", "targetUserId": "대상 사용자 ID" }`
전용 서버와 클라이언트 빌드를 함께 업데이트했습니다. 현재 실행 중인 구버전 방 서버는 종료 후 다시 생성해야 새 강퇴 명령을 처리합니다.
