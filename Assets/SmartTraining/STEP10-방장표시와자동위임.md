# 방장 표시와 자동 위임

방장 ID는 ASP.NET이 관리하고 Unity 전용 서버가 약 1초 간격으로 조회해 참가자에게 동기화합니다.
방장도 일반 참가자처럼 전용 서버에 접속합니다. 방장 퇴장 때문에 전용 서버를 다른 참가자 PC로 옮기지는 않습니다.

## 현재 규칙
- 방 생성 시 생성자를 초기 방장으로 기록합니다. 생성자가 먼저 접속하면 그대로 방장입니다.
- 실제 접속자가 없는 상태에서 다른 참가자가 먼저 접속을 확정하면 그 참가자를 방장으로 지정합니다. 입장 예약만으로는 방장이 되지 않습니다.
- 방장이 퇴장·연결 종료·로그아웃하면 현재 접속한 참가자 중 방 슬롯 번호가 가장 작은 사람에게 자동 위임합니다.
- 이전 방장이 재입장해도 현재 방장을 빼앗지 않습니다.
- 예약자만 남으면 방장은 비어 있고, 다음 참가자가 실제 접속을 확정하면 방장이 됩니다.
- 마지막 참가자가 퇴장하고 예약도 없으면 기존 규칙대로 방과 전용 서버를 정리합니다.

## 확인 순서
1. Unity Play와 ASP.NET을 종료하고 ASP.NET을 다시 빌드·실행합니다.
2. Unity의 ApiLobby 씬에서 로그인하고 방 생성 후 참가합니다.
3. 방 화면 위의 `방장: 닉네임 (나)`, `내 역할: 방장`을 확인합니다. 참가자 목록과 지도에도 `[방장]`이 붙습니다.
4. `Builds/Client/Smart Training Client.exe`를 다른 닉네임으로 실행하고 같은 방에 참가합니다. 두 번째 참가자의 역할은 참가자입니다.
5. 첫 번째 참가자가 방에서 나가거나 Play를 종료합니다. 남아 있는 참가자가 방장으로 바뀌고 연결은 유지됩니다.
6. 첫 번째 참가자가 다시 입장합니다. 기존 방장이 그대로 유지되는지 확인합니다.
7. 현재 방장이 로그아웃합니다. 남아 있는 참가자에게 방장이 넘어가는지 확인합니다.

표시 갱신에는 약 1초와 네트워크 전달 시간이 걸릴 수 있습니다.
이 단계에서는 방장 표시와 자동 위임만 추가했습니다. 수동 위임·강퇴·시작 권한은 별도 단계에서 구현합니다.

## 함수별 변경
- ASP.NET `RoomService.GetRoomMaster`: 등록된 현재 방 서버만 방장 ID를 조회합니다.
- ASP.NET `RoomHub.GetRoomMaster`: 접속 서버가 등록된 방의 정보만 반환합니다.
- 기존 `RoomService.ConfirmConnection`, `ChangeMaster`, `RemoveUserFromRooms`: 실제 접속, 퇴장 및 로그아웃의 방장 결정 규칙을 사용합니다.
- Unity `RoomDedicatedServer.SynchronizeRoomMaster`: ASP.NET 방장 정보를 조회하고 서버에서 네트워크 상태를 갱신합니다.
- Unity `RoomPlayer.SetRoomMasterServer`, `IsRoomMaster`: 서버만 방장 ID를 변경하며 클라이언트는 자신의 역할을 조회합니다.
- Unity `ApiLobbyScreen.DrawRoom`, `RoomMovementView.Draw`: 현재 방장과 참가자별 방장 표시를 보여줍니다.

네트워크 코드를 수정하면 전용 서버와 클라이언트를 함께 빌드해야 합니다. 이번 변경은 두 실행 파일에도 반영했습니다.
