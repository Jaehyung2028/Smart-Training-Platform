# Play 종료 시 서버 사용자 정리 수정

## 원인
기존 ApiLobbyScreen.OnDisable()은 Unity 코루틴을 멈추고 로컬 인증 정보를 지웠습니다.
서버 로그아웃 API를 요청하지 않아 서버에는 사용자·로비 상태가 세션 만료까지 남았습니다.

## 수정 함수
Scripts/TrainingApiClient.cs — LogoutOnShutdown():
- 인증 토큰을 로컬 변수에 보관하고 기존 진행 요청을 중단합니다.
- Unity 코루틴 대신 별도 .NET HttpClient 요청으로 POST /api/Auth/logout을 보냅니다.
- 별도 작업에서 실행하여 Unity 메인 스레드의 코루틴 진행에 의존하지 않습니다.
- 메인 스레드는 정리 완료를 최대 2초 기다립니다. 응답이 빠르면 바로 종료됩니다.
- 토큰·HTTP 본문은 로그에 기록하지 않습니다.
- 로컬 인증 정보를 지우며 세션이 없으면 요청하지 않습니다.
Scripts/ApiLobbyScreen.cs — OnDisable():
- 코루틴 중지 후 LogoutOnShutdown()을 호출합니다.
- 서버 정리를 확인하지 못하면 Console에 경고를 남기고 로컬 정리는 완료합니다.
- 일반 로그아웃 버튼은 기존 비동기 Logout()을 유지합니다.
서버의 기존 UserLifecycleService.LogoutAsync()가 사용자·소속·접속 예약과 소유한 빈 방을 정리합니다.
서버 코드는 변경하지 않았습니다.

## 확인 순서
1. 서버를 실행하고 ApiLobby 씬에서 Play → 로그인합니다.
2. 로비에 입장합니다. 필요하면 빈 방도 생성합니다.
3. 로그아웃 버튼 없이 Unity 상단 Play 버튼을 눌러 종료합니다.
4. 다시 Play하고 같은 닉네임으로 로그인합니다. 중복 이름 오류 없이 로그인되면 정상입니다.
5. 종료한 사용자가 혼자였고 소유한 빈 방만 있었으면 해당 방·로비도 사라집니다.
   다른 사용자 또는 다른 방이 있는 로비는 유지됩니다.

## 제한과 검증
서버가 응답 가능한 정상 종료를 처리합니다.
강제 프로세스 종료·충돌·통신 단절·이미 만료된 토큰에서는 즉시 로그아웃을 보장할 수 없습니다.
실패 시 기존 서버의 세션 만료 정리가 최종 처리합니다.
이 수정 전에 남은 사용자까지 일괄 삭제하지는 않습니다.
테스트 결과: 런타임 빌드 오류/경고 0개, Unity 실제 API 전체 검증 36개 통과.
별도 Unity 검증 프로젝트에서 Play 시작·종료를 수행하여 닉네임 즉시 재사용,
로컬 세션 정리, 반복 종료 안전성, 소유한 빈 방·로비 삭제를 확인했습니다.
자동 테스트의 상태를 보존하기 위해 검증 중 도메인 재로드만 비활성화했고 종료 후 원래 설정을 복원했습니다.
원본 프로젝트의 Play 설정은 변경하지 않았습니다.
