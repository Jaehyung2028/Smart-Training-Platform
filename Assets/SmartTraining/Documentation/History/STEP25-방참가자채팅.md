# STEP25 — 방 참가자 전용 채팅

방에 접속하면 채팅 영역에서 `로비 채팅` 또는 `방 채팅`을 선택할 수 있습니다. 방 채팅은 ASP.NET SignalR로 실제 접속이 확정된 같은 방 참가자에게만 전달하며, 플레이어 동기화는 기존 Unity Netcode를 사용합니다.

## 구현 위치

- 서버 `LobbyUpdatesHub.SubscribeRoomChat()`, `SendRoomChat()` — 방 채팅 연결 등록과 전송.
- 서버 `LobbyRoomUpdates.SubscribeRoomChat()`, `PrepareRoomChat()` — 현재 인증·실접속·입장 토큰·연결 세대 검증 및 수신자 선별.
- 서버 `RoomService.CanUseRoomChat()` — 방이 존재하고 접속이 확정된 참가자인지 확인. 예약만 된 사용자, 이전 접속 토큰, 닫는 중인 방, 종료한 서버는 거부.
- Unity `ApiLobbyScreen.RoomChat.cs`의 `BindRoomChat()`, `SendRoomChat()`, `ReceiveRoomChat()` — 자동 연결, 전송, 수신.
- Unity `SyncChatRoom()` — 강퇴·연결 끊김·방 변경 시 방 메시지와 해당 입력을 정리.
- Unity `RoomNetworkClient.AdmissionToken` — 현재 방 연결의 내부 접속 토큰. 외부 저장 없이 연결 종료 시 삭제.

## 규칙

- 로비 채팅은 같은 로비 전체, 방 채팅은 같은 방의 접속 확정 참가자만 수신합니다.
- 방장과 일반 참가자 모두 전송할 수 있으며 대기 중·진행 중에 사용 가능합니다.
- 두 채널은 별도 목록에 최근 수신 100개씩 표시합니다. 채널 전환 시 입력을 지워 잘못된 대상에 보내는 일을 줄입니다.
- 메시지 1~200자, 줄바꿈·제어 문자 불가. 사용자당 1초에 한 번 전송 제한을 두 채널이 공유합니다.
- 강퇴·퇴장·재접속 때 이전 방 메시지는 삭제합니다. 같은 로비의 메시지는 유지합니다.
- 수신자별 연결 세대 ID로 같은 방 재접속 후 늦게 도착한 이전 연결 메시지를 거릅니다. 접속 토큰은 메시지 내용에 포함하지 않습니다.
- SignalR 연결만 일시 재연결되면 현재 방 메시지 표시는 유지하면서 새 연결을 등록합니다.
- 서버 기록 저장·접속 전 메시지 조회·연결 중 누락 메시지 복구는 미구현입니다.
- 전송 실패 시 입력과 안내를 표시하며 결과가 불확실한 메시지를 자동 재전송하지 않습니다.

## 직접 확인

1. ASP.NET 서버를 재시작하고 Unity 에디터와 클라이언트 빌드를 서로 다른 닉네임으로 실행합니다.
2. 같은 로비·같은 방에 입장합니다. 채팅 영역에서 `방 채팅`을 선택하고 메시지를 전송합니다.
3. 양쪽 방 메시지 목록에 닉네임·시각·내용이 표시되는지 확인합니다.
4. 같은 로비에 있지만 방에 입장하지 않은 사용자는 방 메시지를 받지 않는지 확인합니다.
5. 같은 로비의 다른 방에서는 방 메시지가 분리되고, `로비 채팅`은 함께 수신되는지 확인합니다.
6. 참가자를 강퇴한 뒤 다시 입장시켜 이전 방 메시지가 사라지고 새 메시지는 정상 수신되는지 확인합니다.
7. 로비·방 채팅을 번갈아 빠르게 전송해도 1초 제한이 적용되는지 확인합니다.

자동 검증: 서버 `Tests/Checks/RoomChatChecks.cs`, Unity `Editor/RoomChatChecks.cs` 및 기존 멀티 접속 통합 검증.
