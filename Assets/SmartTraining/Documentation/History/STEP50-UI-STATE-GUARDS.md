# UI 작업 잠금과 화면 전환 정리

디자인 작업 전에 버튼 연속 입력, 처리 중 안내, 화면 전환 시 남는 입력값을 정리했습니다.

## 변경한 함수

- `ApiLobbyScreen.RunOperation()` : 작업을 시작하는 순간 버튼을 잠그고 작업별 진행 문구를 표시합니다. 기존 실행 중 검사도 유지하여 직접 호출이 반복되어도 요청을 중복 전송하지 않습니다.
- `ApiLobbyScreen.Execute()` : 작업이 끝나면 잠금과 진행 문구를 해제하고 화면을 바로 갱신합니다.
- `ApiLobbyScreen.ClearRoomPasswords()`, `ClearView()`, `LeaveLobby()`, `LeaveRoom()` : 퇴장과 세션 종료 시 비밀번호 초안을 정리합니다.
- `ApiLobbyScreen.ReconnectRoom()` : 재접속에 사용할 비밀번호를 먼저 보관하여 퇴장 정리 후에도 비밀번호 방에 정상 재접속합니다.
- 각 UGUI 뷰의 `RefreshState()`, `ResetTransientState()` : 숨겨진 진행 창, 설정 창, 확인 창, 지도, 입력란과 키보드 선택을 정리합니다. 로비의 방 목록 선택 등은 해당 로비를 떠날 때 초기화합니다.
- `RoomUguiView.UpdateParticipantActions()` : 참가자 버튼의 잠금은 목록 갱신 주기와 관계없이 즉시 반영합니다.

입장 처리 중에는 취소 버튼을 사용할 수 있으며, 취소 이후 서버 예약 정리가 끝날 때까지 일반 작업은 잠깁니다. 프리팹 구성과 화면 배치는 변경하지 않았습니다.

## 직접 확인

1. 로그인·방 생성·입장 버튼을 빠르게 여러 번 눌러 결과가 한 번만 적용되는지 확인합니다.
2. 처리 중에는 해당 작업명이 표시되고 다른 작업 버튼이 잠기는지 확인합니다.
3. 비밀번호 방에 들어갔다가 연결을 끊고, 비밀번호를 입력해 재접속합니다.
4. 방 설정 창이나 지도를 연 상태에서 퇴장·강퇴·연결 끊김이 발생하면 이전 창과 입력값이 사라지는지 확인합니다.
5. 생성 창에 비밀번호를 입력하고 로그아웃한 뒤 재로그인하여 이전 입력값과 방 선택이 남지 않는지 확인합니다.

## 자동 검증 재실행

`Tests/MultiClient/Run-UguiStateGuards.ps1`에 `-ServerProject`, `-ClientExecutable`, `-EvidenceRoot`를 지정합니다. 서버는 빌드된 Debug/net8.0 DLL과 방 서버 실행 파일이 있는 프로젝트 폴더, 클라이언트는 Development Build 실행 파일이어야 합니다.

독립 API 포트 51464를 사용하므로 해당 포트와 테스트용 방 서버 포트가 사용 중이지 않아야 합니다. 테스트 전용 로그인·방 데이터만 만들며 테스트가 생성한 프로세스는 종료합니다. 연속 클릭 검사에서는 서버의 실제 HTTP 요청 횟수도 확인합니다.
