# 방 입장 취소

## 사용 방법
방 참가 후 나타나는 진행 화면에서 **입장 취소**를 누릅니다. 취소 처리 중에는 버튼이 비활성화되고, 정리가 끝나면 로그인과 로비 소속을 유지한 채 로비 화면으로 돌아갑니다.

재접속 진행 중에도 동일하게 취소할 수 있습니다. 입장 완료 후에는 기존 **방에서 나가기**를 사용합니다.

## Unity 변경 함수
- `ApiLobbyScreen.RoomConnection.cs`의 `DrawRoomJoinProgress()`: 입장 취소 버튼과 취소 진행 안내
- `RequestCancelRoomJoin()`: 진행 중인 입장에 취소 의사를 전달. 중복 취소 클릭은 무시
- `JoinRoom()` / `JoinRoomCore()`: 예약·Netcode 연결·서버 확인 단계에서 취소를 확인하고, 이미 접속이 확정됐더라도 `LeaveRoom()`으로 정리
- `TrainingApiClient.JoinRoom()` / `Send()`: 입장 요청에 취소 조건을 전달하고 해당 HTTP 요청을 중단. 인증 토큰 갱신 요청은 중단하지 않음
- `RoomNetworkClient.Connect()`: 주소 확인 및 연결 대기를 취소하고 생성한 네트워크 연결을 정리
- `ClearView()`: 종료·세션 초기화 시 취소 표시 초기화

## ASP.NET 변경 함수
- `RoomController.JoinRoom()`: `HttpContext.RequestAborted`를 서비스에 전달
- `RoomService.JoinRoom()`: 취소된 요청은 예약을 만들지 않으며, 서버 준비 대기 중 취소되면 본인의 예약을 해제
- 대기 중인 다른 참가자가 없다면 시작 중인 불필요한 방 서버도 정리. 다른 참가자의 예약이 있다면 공유 서버 시작은 유지
- 취소한 서버 실행의 오래된 등록 토큰은 재사용할 수 없음

입장 취소는 코루틴을 강제로 중단한 뒤 끝내는 방식이 아닙니다. 취소 상태를 전달하고 기존 퇴장·내 정보 조회를 거쳐 서버 예약과 실제 연결을 함께 정리합니다. 서버 연결 문제로 정리 결과를 확인하지 못하면 기존의 `정리 확인:` 오류 안내가 표시됩니다.

## 자동 검사
서버 검사 482개, Unity·Netcode 연동 검사 385개, 별도 실행 파일 3개의 검사 15개를 통과했습니다.

- 서버 `JoinCancellationChecks.Run()`: 예약 전 취소, 준비 중 취소, 공유 서버 대기, 재입장, 이미 확정된 접속 퇴장, 실제 HTTP 요청 중단 및 늦은 등록 거부
- Unity `RoomJoinCancellationChecks.Run()`: 즉시 취소, Netcode 연결 단계 취소, ASP.NET과 Netcode가 접속을 확정한 뒤 취소, 재참가, 재접속 취소, 중복 클릭 및 완료된 입장에 대한 취소 무시
- 개발 빌드 검사용 `MultiClientProbe`의 취소 명령은 입장 처리 중에도 전달 가능. 일반 실행에서 이 도구는 활성화되지 않음
- `Tests/MultiClient/Run-JoinCancellation.ps1`: 실제 개발 클라이언트에서 취소·예약 정리 후 재입장 및 기존 멀티 흐름 확인. 실행 인자는 STEP35의 검사 스크립트와 동일

## 직접 확인
1. 서버와 Unity를 다시 실행합니다.
2. 방 참가 후 진행 화면에서 입장 취소를 누릅니다. 정상 연결이 빠르면 버튼이 짧게 보일 수 있습니다.
3. 취소 안내 후 로그인과 현재 로비가 유지되고, 방 참가를 다시 할 수 있는지 확인합니다.
4. 다른 참가자가 있는 방에서 취소해도 기존 참가자의 연결과 방 정보가 유지되는지 확인합니다.
5. 연결 끊김 후 이전 방 재접속 중 취소하면 재접속 대상이 지워지고 로비에 남는지 확인합니다.

입장이 이미 완료되어 진행 화면이 사라졌다면 기존 퇴장 버튼을 사용합니다. 표시를 위해 정상 접속을 인위적으로 늦추지는 않습니다.
