# STEP14 — 연결 끊김 감지와 재접속

## 변경한 함수
- `RoomNetworkClient.Connect`: 1초 간격의 전송 계층 heartbeat, 10초 무응답 기준 설정.
- `RoomDedicatedServer.Start`: 같은 기준으로 연결 끊긴 참가자를 정리. 방장 퇴장 시 기존 자동 위임 적용.
- `ApiLobbyScreen.HandleConnectionLost`: 이전 연결·입장 예약을 정리하고 로그인/로비를 유지. 일반 연결 끊김은 재접속 대상 저장, 강퇴는 저장하지 않음.
- `ApiLobbyScreen.ReconnectRoom`: 이전 정리를 다시 확인하고 최신 방 정보(잠금·빈 자리)를 조회한 뒤 새 입장 예약과 새 플레이어로 접속.
- `ApiLobbyScreen.ForgetReconnect`: 재접속 성공, 명시적 퇴장·로그아웃·로비 이동 시 대상 제거.

## 확인 방법
1. ASP.NET 서버를 중지하고 다시 빌드·실행. Unity에서 ApiLobby 씬 Play.
2. 두 클라이언트를 같은 방에 접속. 한 클라이언트의 네트워크를 잠시 끊었다 복구.
3. 연결 끊김을 감지하면 해당 클라이언트는 로비로 복귀하며 로그인은 유지. 다른 참가자에게 떠난 플레이어가 사라지는지 확인.
4. 로비의 **이전 방에 다시 접속** 버튼을 눌러 참가자 수와 플레이어가 중복되지 않는지 확인.
5. 재접속 전 방장이 입장을 잠그면 거절, 열면 재접속 가능. 재접속한 이전 방장이 현재 방장 권한을 빼앗지 않음.
6. 강퇴 및 직접 퇴장에는 재접속 대상 버튼이 생기지 않음.

## 동작 범위
- 무응답 판정은 약 10초이며 프레임 처리·서버 통신 시간 때문에 정리 완료 시간은 달라질 수 있음.
- 자동 재접속은 하지 않고 사용자가 버튼으로 재시도. ASP.NET 연결도 끊겼다면 복구 후 버튼을 다시 눌러 정리부터 확인.
- 마지막 참가자가 떠나 방이 삭제되면 이전 방 접속 불가. 새 방 생성 또는 다른 방 선택.
- 재입장은 새 접속으로 처리되어 이전 위치·방장 역할을 복원하지 않음.
