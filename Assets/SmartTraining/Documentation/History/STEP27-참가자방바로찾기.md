# STEP27 — 참가자 목록에서 방 바로 찾기

현재 로비 참가자 중 방에 접속 중인 사용자 아래에 `닉네임의 방 보기` 버튼을 표시합니다. 버튼을 누르면 서버에서 참가자의 최신 위치와 방 정보를 조회한 뒤 해당 방의 상세 정보로 이동합니다.

## 구현 위치

- `ApiLobbyScreen.Participants.cs`의 `DrawLobbyParticipants()` — 접속 중인 참가자에게 방 보기 버튼 표시.
- `ApiLobbyScreen.ParticipantRoom.cs`의 `ViewParticipantRoom()` — 현재 사용자 상태·참가자 위치·방 정보 조회 및 표시. 조회하는 동안 상대가 퇴장하거나 방을 옮기면 안내.
- `ParticipantRoomViewStatus()` — 입장 잠김·진행 중·정원 초과·비밀번호 상태에 맞는 안내.
- `ScrollToSelectedRoom()` — 선택한 방의 상세 정보가 보이도록 스크롤 이동.
- `ResetRoomBrowser()` — 해당 방을 숨길 수 있는 기존 검색·필터 조건을 초기화.

## 동작

- 다른 로비 목록을 살펴보던 중에도 현재 소속 로비로 돌아와 해당 방을 선택합니다.
- 닉네임 대신 사용자 ID로 최신 참가자를 조회합니다. 인원수나 닉네임만으로 대상을 추정하지 않습니다.
- 상세 보기만으로 방 입장이나 예약을 생성하지 않습니다. 입장은 기존 `선택한 방에 참가` 버튼을 눌러 진행합니다.
- 기존 비밀번호 입력을 지우고 비밀번호 방은 새로 입력하도록 합니다.
- 잠긴 방·진행 중인 방·가득 찬 방도 상세 정보는 볼 수 있지만, 기존 입장 제한은 그대로 적용됩니다.
- 자신의 방 접속이나 예약이 남아 있으면 방 보기 버튼을 비활성화하고 먼저 명시적으로 퇴장·예약 취소하도록 안내합니다.
- 실제 입장 순간에도 기존 서버 검증을 수행하므로 상세 조회 이후 정원이나 잠금 상태가 바뀌면 서버가 입장을 거절합니다.

## 직접 확인

1. Unity 에디터와 클라이언트 빌드를 서로 다른 닉네임으로 실행해 같은 로비에 입장합니다.
2. 한 사용자가 방에 접속하고 다른 사용자는 로비에서 대기합니다.
3. 대기 중인 화면의 `현재 로비 참가자`에서 접속 중인 사용자의 `방 보기`를 누릅니다.
4. 해당 방이 선택되고 상세 정보로 화면이 이동하는지 확인합니다.
5. 검색·필터로 방을 숨겨둔 상태에서도 버튼을 누르면 필터가 초기화되는지 확인합니다.
6. 비밀번호·입장 잠금·정원 제한이 있는 방에서는 안내와 기존 참가 제한이 유지되는지 확인합니다.
7. 상대가 퇴장한 뒤에는 자동 갱신 목록에서 방 보기 버튼이 사라지는지 확인합니다.

자동 검증은 Unity `Editor/ParticipantRoomChecks.cs`와 기존 멀티 접속 통합 검증에 포함됩니다.
