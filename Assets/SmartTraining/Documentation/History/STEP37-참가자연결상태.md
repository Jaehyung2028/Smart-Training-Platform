# 참가자 연결 상태 표시

방 안의 참가자 목록에 서버가 판정한 연결 상태를 지연 시간과 함께 표시합니다.

| 표시 | 프로젝트의 판정 기준 |
| --- | --- |
| 연결 측정 중 | 참가자가 생성됐으나 응답 또는 지연 측정이 아직 없음 |
| 정상 연결 | 최근 응답이 있고 왕복 지연이 500ms 미만 |
| 응답 지연 | 최근 응답이 있고 왕복 지연이 500ms 이상 |
| 연결 확인 중 | 서버가 마지막 응답을 받은 뒤 3초 이상 경과 |

클라이언트는 자신의 참가자에서 1초마다 응답 RPC를 보냅니다. 서버는 자신의 시계로 수신 시각을 기록하고 약 1초마다 상태를 판정합니다. 따라서 응답 중단 후 연결 확인 중 표시는 약 3~4초 뒤 나타날 수 있습니다. 응답이 다시 들어오면 다음 판정에서 정상 연결 또는 응답 지연으로 돌아옵니다.

이 상태는 참가자와 Unity 전용 방 서버 사이의 연결 안내입니다. ASP.NET 알림 연결 상태와는 별도로 표시합니다. 연결 확인 중에는 지연 시간이 최신 값이 아닐 수 있어 `마지막 측정`으로 표시합니다.

## 참가자 제거와 방장 위임
연결 확인 중이라는 표시만으로 퇴장시키거나 방장을 바꾸지 않습니다. 기존 Netcode 종료 감지와 ASP.NET의 접속 정리 절차가 완료되어야 참가자가 제거되고 방장이 위임됩니다. 준비·진행 상태·권한 규칙도 기존대로 유지합니다.

## 변경 함수
- `RoomPlayer.HeartbeatRpc()`: 현재 플레이어의 소유자만 보낼 수 있는 응답. 서버가 수신 시각 기록
- `RoomPlayer.Update()`: 이동·메뉴 조작 여부와 관계없이 소유자가 주기적으로 응답 전송
- `RoomPlayer.SampleConnectionHealthServer()`: 서버 측 지연과 응답 경과 시간으로 상태를 계산하고 NetworkVariable로 전체 참가자에게 전달
- `RoomPlayer.ConnectionStatusLabel`: 표시할 상태 문구
- `RoomDedicatedServer.SampleParticipantLatency()`: 지연 측정과 연결 상태 판정을 함께 수행
- `ParticipantConnectionHealth.Evaluate()`: 표시 기준 계산. `Label()`은 문구 변환
- `RoomMovementView.Draw()`: 참가자 행에 상태 및 측정 시간 표시

상태 NetworkVariable의 쓰기 권한은 서버에만 있습니다. 클라이언트가 다른 참가자의 연결 상태를 정상으로 덮어쓰거나 자신의 시간을 서버에 전달하는 방식은 사용하지 않습니다.

## 검증
Unity·Netcode 연동 검사 396개와 실제 클라이언트 프로세스 3개의 검사 14개를 통과했습니다.

실제 클라이언트 실행 파일 3개에서 방장 프로세스를 강제 종료했습니다. 남은 참가자가 종료 전까지 방장을 유지하면서 연결 확인 중 표시를 받고, 이후 종료 확정·자동 위임·새 참가자 입장까지 정상 동작했습니다.

Unity 자동 검사에는 초기 측정, 500ms 경계값, 응답 중단과 회복의 판정 기준, 모든 참가자에게 정상 상태 전파, 클라이언트의 상태 변경 거부 검사를 추가했습니다. 실제 지연을 500ms로 만드는 네트워크 지연 주입 검사는 이번 검사에 포함하지 않습니다.
실제 Netcode 연결을 유지한 상태에서 한 소유자의 응답 전송을 잠시 멈추고, 다른 클라이언트에 연결 확인 중이 표시되는지와 응답 재개 후 정상 상태로 복구되는지도 검사합니다.

독립 실행 검사는 `Tests/MultiClient/Run-ConnectionHealth.ps1`로 재실행합니다. 서버·클라이언트 경로 및 증거 폴더 인자는 STEP35와 동일합니다.

## 직접 확인
1. 서버와 Unity를 다시 실행하고 새로 빌드된 클라이언트를 사용합니다. 플레이어의 동기화 데이터가 추가되어 클라이언트와 전용 서버를 함께 갱신해야 합니다.
2. 두 참가자가 방에 들어가면 참가자 행에 연결 측정 중 다음 정상 연결이 표시되는지 확인합니다.
3. 한 클라이언트 프로세스를 강제 종료하고 다른 클라이언트에서 약 3~4초 뒤 연결 확인 중이 표시되는지 확인합니다.
4. 종료가 확정된 뒤 목록에서 제거되고, 방장이 종료된 경우 자동 위임되는지 확인합니다.

연결 확인 중은 서버가 응답을 기다리는 단계이며, 참가자가 확실히 종료됐다는 뜻으로 표시하지 않습니다.
