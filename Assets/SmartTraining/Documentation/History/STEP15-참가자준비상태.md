# STEP15 — 참가자 준비 상태

## 변경한 함수
- `RoomPlayer.SetReadyRpc(bool)`: 자기 플레이어의 소유자만 요청할 수 있으며 전용 서버가 준비 상태를 변경합니다. `IsReady`는 서버 기록 값을 읽습니다.
- `RoomNetworkClient.SetReady(bool)`: 연결·플레이어 생성·소유권을 확인한 뒤 요청합니다.
- `RoomNetworkClient.GetReadiness()`: 현재 동기화된 참가자의 준비 인원과 전체 인원을 계산합니다. 빈 방이나 플레이어 확인 전에는 전원 준비 완료로 표시하지 않습니다.
- `ApiLobbyScreen.SetReady(bool)`: 준비/준비 취소 버튼 처리, 서버에서 동기화된 상태를 확인한 뒤 완료 표시합니다.
- `ApiLobbyScreen.DrawRoom`, `RoomMovementView.Draw`: 준비 인원, 전원 준비 여부, 각 참가자의 준비 상태 표시.

## 확인 방법
1. ASP.NET 서버를 다시 실행하고 Unity ApiLobby 씬에서 Play합니다. 전용 서버 빌드는 최신 파일로 반영되어 있습니다.
2. 서로 다른 닉네임으로 두 클라이언트를 같은 방에 접속합니다.
3. 처음에는 `0/2명 준비 완료`인지 확인합니다. 방장도 준비 인원에 포함됩니다.
4. 한 참가자가 준비를 누르면 양쪽 화면에 `1/2`, 해당 참가자만 준비 완료로 표시됩니다.
5. 두 참가자가 준비하면 `2/2`와 전원 준비 완료가 표시됩니다.
6. 준비 취소 시 전원 준비 표시가 사라지고 해당 참가자만 준비 전으로 바뀝니다.
7. 세 번째 참가자가 들어오면 준비 전 상태로 시작하며 기존 참가자의 준비 상태는 유지됩니다.
8. 참가자가 퇴장하면 전체 인원에서 제외됩니다. 재접속 또는 강퇴 후 새 입장은 준비 전으로 시작합니다.
9. 방장 위임 자체로 준비 상태를 바꾸지는 않습니다.

## 설계 범위
준비 상태는 현재 방 접속 동안 유지되는 멀티 상태로, Unity Netcode 전용 서버에서 관리합니다. ASP.NET 사용자·로비·방 관리 API에 중복 저장하지 않습니다. 전원 준비 표시는 현재 클라이언트에 동기화된 참가자를 기준으로 하며, 훈련 시작 권한 판단 기능은 아직 없습니다. 실제 훈련 시작은 추후 콘텐츠 단계에서 전용 서버의 참가자 상태를 다시 검증하도록 연결해야 합니다.
