# 에디터 종료 정리 재보완

## 확인된 문제
원본 Unity Editor.log에 종료 시 서버 로그아웃 확인 실패 경고가 있었습니다.
이전 방식은 OnDisable에서 별도 .NET HTTP 요청을 최대 2초 기다렸으며 실제 환경에서 완료되지 않았습니다.
정확한 네트워크 실패 원인은 기존 로그에 기록되지 않았습니다.

## 새 방식
Scripts/Diagnostics/EditorSessionCleanup.cs — Enqueue(), Pump(), BeforeReload():
- 종료할 토큰과 주소를 Unity 에디터 SessionState에 임시 보관합니다.
- SessionState는 도메인 재로드를 통과하며 Unity 에디터 종료 시 사라지는 세션 저장소입니다.
- EditorApplication.update에서 UnityWebRequest로 로그아웃을 실행합니다.
- 로그인과 동일한 Unity 네트워크 처리를 사용하며 TLS 검증은 우회하지 않습니다.
- 요청 5초 제한, 실패 시 최대 3회 시도합니다.
- 도메인 재로드 전 진행 요청을 중단하고 재로드 후 이어서 처리합니다.
- 401이면 refresh를 한 번 시도한 뒤 갱신 토큰으로 로그아웃합니다.
- 정리 완료/최종 실패 때 토큰을 세션 저장소에서 제거합니다. 로그에는 토큰을 출력하지 않습니다.
- 완료 시 Console에 'Play 종료: 서버 사용자 정리가 완료됐습니다.'를 표시합니다.
Scripts/Client/Api/TrainingApiClient.cs — LogoutOnShutdown():
- 에디터에서는 종료 요청을 위 정리 큐로 전달합니다.
- 빌드 앱의 기존 최대 2초 종료 요청은 유지합니다.
Scripts/Client/Controllers/ApiLobbyScreen.cs — WaitingForExitCleanup, OnGUI(), Run():
- 이전 종료 정리가 진행 중이면 '이전 접속을 정리하는 중…'을 표시하고 요청 버튼을 잠시 비활성화합니다.
- 정리 완료 후 로그인할 수 있습니다.
Editor/DomainReloadExitTest.cs:
- 기본 도메인 재로드 상태의 Play 시작·종료, 닉네임 재사용, 빈 방·로비 정리 검증.
- 토큰을 테스트 지속용 저장소에 넣지 않습니다. 테스트 상태는 이름/로비 ID만 유지합니다.
Editor/ApiSmokeTest.cs: 종료 정리 완료를 기다린 후 닉네임 재사용을 검증하도록 변경했습니다.

## 재확인
1. 이전 실패로 서버에 남은 사용자는 옛 토큰이 없으므로 이 수정만으로 정리할 수 없습니다.
2. 개발용 서버를 한 번 중지 후 다시 실행합니다. 메모리의 사용자·로비·방 정보가 초기화됩니다.
3. Unity 스크립트 컴파일 완료 후 ApiLobby 씬 Play → 로그인합니다.
4. 로그아웃 버튼 없이 Play를 종료합니다.
5. Console에서 정리 완료 메시지를 확인합니다.
6. 다시 Play → 같은 닉네임으로 로그인합니다.
서버를 재시작하면 현재 개발용 메모리 데이터가 모두 초기화되므로 다른 테스트 사용자가 있다면 먼저 종료해주세요.

## 검증 범위
Unity 라이브러리 런타임 빌드 오류/경고 0개.
별도 Unity 검증 프로젝트와 실제 임시 서버에서 기존 36개 검증 통과.
기본 도메인 재로드 상태에서도 Play 종료 후 닉네임 즉시 재사용과 소유한 빈 방·로비 정리 추가 3개 검증 통과.
원본 서버/프로젝트 Play 설정은 변경하지 않았습니다.
서버 통신이 불가능하거나 에디터 자체를 강제 종료하면 즉시 정리는 보장되지 않으며 기존 서버의 세션 만료 정리가 처리합니다.
