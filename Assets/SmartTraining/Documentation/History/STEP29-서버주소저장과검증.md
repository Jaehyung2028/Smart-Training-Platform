# STEP29 — 서버 접속 주소 저장·검증

로그인 화면에서 서버 주소를 저장하거나 기본 주소로 초기화할 수 있습니다. 저장한 주소는 다음 플레이·실행 시 불러옵니다. 주소 저장 자체가 서버 접속이나 로그인은 아닙니다.

## 구현 위치

- `ServerAddress.TryNormalize()` — http/https, 주소 길이, 포트, 공백/제어 문자, 사용자 정보/쿼리/조각 검증.
- `ServerAddressSettings.Save()`, `TryLoad()`, `Reset()` — 앱 설정에 공개 서버 기본 주소 하나만 저장·불러오기·삭제.
- `ApiLobbyScreen.ServerAddress.cs`의 `LoadServerAddress()`, `SaveServerAddress()`, `ResetServerAddress()` — 화면 초기화 및 저장·초기화 버튼 처리.
- `DrawServerAddressSettings()` — 입력과 정리된 연결 주소, 저장 결과 표시.
- `TrainingApiClient()` / `EnsureClient()` — 실제 API도 동일한 검증 적용. 로그인이나 방 연결 중 다른 서버로 바꾸는 것은 거절.

## 동작

- http/https만 허용하며 앞뒤 일반 공백과 마지막 `/`를 정리합니다.
- `https://localhost:7087/swagger/index.html`을 붙여넣으면 `https://localhost:7087`로 연결합니다. `/training/swagger`처럼 앱 기본 경로가 있으면 `/training`을 보존합니다.
- 주소에 사용자 정보, 쿼리, `#` 조각, 제어 문자나 내부 공백이 있으면 거절합니다. 접속 대상에는 `0.0.0.0`, `::` 대신 실제 서버 IP 또는 localhost를 사용합니다.
- `주소 저장`은 주소 형식을 검증하고 저장합니다. 서버 실행 여부는 `서버 연결 확인`으로 확인합니다.
- 저장하지 않은 입력은 다음 실행에 유지하지 않습니다. 인증 토큰·입장 토큰·비밀번호·닉네임을 주소 설정에 저장하지 않습니다.
- 로그인 또는 작업 처리 중에는 저장·초기화를 비활성화합니다. 다른 서버로 이동하려면 먼저 로그아웃합니다.
- `기본 주소로 초기화`는 해당 설정만 삭제하고 씬에 지정된 기본 주소로 돌아옵니다.
- 손상된 저장 주소는 기본값으로 대체해 표시하고 다시 저장·초기화하도록 안내합니다.
- 주소 설정은 각 실행 환경의 앱 설정을 사용합니다. 에디터와 클라이언트 빌드는 각각 저장하고 확인해주세요.
- 다른 PC에서 실제 방에 접속하려면 서버 바인딩·광고 주소·포트 접근 설정도 맞아야 합니다. 이 단계에서는 서버 실행 설정을 변경하지 않습니다.

## 직접 확인

1. Unity 플레이를 다시 시작하고 로그인 전에 서버 주소를 입력합니다.
2. Swagger 주소를 붙여넣어 `연결할 주소`가 API 기본 주소로 정리되는지 확인합니다.
3. `서버 연결 확인`으로 응답을 확인하고 `주소 저장`을 누릅니다.
4. 플레이 종료 후 다시 시작하거나 클라이언트 앱을 재실행해 저장한 주소가 불러와지는지 확인합니다.
5. 잘못된 주소를 저장하면 안내가 나오고 이전 저장 주소는 유지되는지 확인합니다.
6. 로그인 후에는 주소 저장·초기화가 막히는지 확인합니다.
7. 로그아웃 후 `기본 주소로 초기화`를 눌러 기본값으로 복구되는지 확인합니다.

자동 검증은 `Editor/ServerAddressChecks.cs`, `ServerAddressScreenChecks.cs`와 기존 멀티 연동 검증을 사용합니다. 검증은 별도의 임시 설정 키를 사용하고 해당 키만 삭제합니다.
