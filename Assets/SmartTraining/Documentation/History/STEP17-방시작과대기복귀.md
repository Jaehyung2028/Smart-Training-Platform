# STEP17 — 방 시작과 대기 복귀

## 구현 범위
훈련 콘텐츠를 실행하는 기능이 아니라 방의 대기·진행 상태를 관리합니다. 서버 프로세스의 실행 상태와 방 진행 상태는 별개입니다.

## 변경한 함수
- `RoomPlayer.RequestPhaseRpc`: 자기 플레이어의 소유자만 요청. 전용 서버의 방장·준비 검증으로 전달.
- `RoomDedicatedServer.RequestRoomPhase`, `ChangeRoomPhase`: 전원 접속·준비 확인, 중복 요청 및 전환 중 준비 변경 차단. 실제 서버 응답 후 참가자에게 결과 표시.
- `RoomService.SetRoomPhase`, `RoomHub.SetRoomPhase`: 등록된 서버·현재 방장·현재 입장 토큰 확인. 시작 시 참가자 목록 일치와 미완료 예약 없음 확인 후 원자적으로 진행 상태 변경.
- `RoomDedicatedServer.ApplyRoomPhase`: 상태 변경 번호를 비교해 과거 조회 응답이 새 진행 상태를 덮어쓰지 않도록 처리. 대기 복귀 시 전원 준비 초기화.
- `ApiLobbyScreen.ChangeRoomPhase`: 방장 전용 시작·대기 복귀 버튼, 참가자 상태 표시.
- `RoomService.JoinRoom`, `ValidateConnection`, `ConfirmConnection`, `UpdateRoomSettings`: 진행 중 신규 입장·설정 변경 차단. 기존 연결 확정의 동일 토큰 재전송은 유지.

## 확인 방법
1. ASP.NET을 재시작하고 두 클라이언트가 같은 방에 접속합니다.
2. 대기 중에는 각자 준비를 누릅니다. 전원 준비 전 방장의 시작 버튼은 비활성화됩니다.
3. 전원 준비가 완료되면 방장이 **전원 준비 확인 후 시작**을 누릅니다. 양쪽에 진행 중 표시가 나타납니다.
4. 진행 중 준비 변경·방 설정 변경이 차단됩니다. 빈 자리가 있어도 새 참가자는 입장할 수 없습니다.
5. 방장이 **대기 상태로 복귀**를 누르면 모든 참가자가 준비 전 상태로 돌아옵니다. 다시 준비하고 시작할 수 있습니다.
6. 진행 중 방장 위임은 진행 상태를 유지합니다. 새 방장만 대기 복귀할 수 있습니다.
7. 입장 예약자가 아직 접속하지 않았다면 시작은 거절됩니다. 예약자가 접속 후 준비하거나 예약을 취소한 뒤 재시도합니다.
8. 기존 수동 입장 잠금은 별도로 유지됩니다. 대기 복귀 후에도 수동 잠금이 남아 있으면 신규 입장은 거절됩니다.

진행 중 연결이 끊긴 참가자는 대기 복귀 후 새 예약으로 다시 접속할 수 있습니다. 마지막 참가자가 떠나 방이 삭제되면 새 방이 필요합니다. 전용 서버가 종료되면 API는 진행 상태를 대기로 초기화하고 기존 접속을 정리합니다. GitHub 업로드는 별도 요청 시 진행합니다.
