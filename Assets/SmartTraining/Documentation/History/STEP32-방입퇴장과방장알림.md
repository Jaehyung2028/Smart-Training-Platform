# STEP32 — 방 입장·퇴장·방장 변경 알림

방 안에 '방 알림' 영역을 추가했습니다.
접속 이후 관측한 참가자 입장, 퇴장, 방장 변경을 이름과 시각으로 표시하고 최근 20개를 보관합니다.
'방 알림 지우기'는 표시 기록만 지우므로 기존 참가자를 다시 입장했다고 알리지 않습니다.

## 주요 함수
- RoomNoticeTracker.Observe(): 이전 참가자 목록과 현재 목록을 비교해 알림을 생성합니다.
- ApiLobbyScreen.UpdateRoomNotices(): 로그인 사용자와 실제 방 연결을 확인하고 동기화된 Netcode 상태를 읽습니다.
- ApiLobbyScreen.DrawRoomNotices(): 이름과 관측 시각을 표시합니다. 이름은 서식 코드로 해석하지 않습니다.
- ClearRoomNotices(): 방 퇴장, 로그아웃, 연결 변경 시 이전 기록과 비교 기준을 정리합니다.

처음 접속했을 때는 기존 참가자와 방장을 비교 기준으로만 저장합니다.
접속 예약만으로는 입장 알림을 생성하지 않습니다.
수동 위임과 자동 위임은 실제 동기화된 방장 식별자로 확인하며, 아직 이름이 동기화되지 않은 방장 알림은 기다립니다.
같은 사용자의 새 연결이 퇴장 관측 전에 나타나면 '다시 접속했습니다'로 표시합니다.
퇴장과 재입장을 각각 관측했다면 각각 퇴장·입장 알림으로 표시합니다.
방 서버 연결의 재접속 또는 다른 방으로 이동하면 이전 알림을 지우고 새 기준을 저장합니다.
ASP.NET 알림 연결만 다시 연결되는 경우에는 현재 Unity 방 연결의 알림을 유지합니다.

## 확인 방법
1. Unity 플레이를 다시 시작하고 새 클라이언트 빌드를 실행합니다.
2. 먼저 방에 들어간 사용자는 다른 사용자가 입장할 때 이름과 입장 알림을 확인합니다.
3. 나중에 입장한 사용자는 기존 참가자가 새로 입장했다고 표시되지 않는지 확인합니다.
4. 방장을 수동 위임하거나 방장이 퇴장하면 남아 있는 참가자가 방장 변경 알림을 받는지 확인합니다.
5. 알림을 지운 뒤 같은 알림이 반복되지 않는지 확인합니다.
6. 방을 나갔다가 다시 접속하면 이전 기록이 남아 있지 않은지 확인합니다.

알림은 클라이언트가 관측한 현재 상태 변화입니다. 서버에 저장되는 감사 기록은 아닙니다.
접속 전에 발생한 사건을 재생하지 않으며, 프레임 사이에 여러 변화가 일어나면 하나의 상태 변화로 관측할 수 있습니다.
퇴장 사유는 목록만으로 판단하지 않으므로 강퇴나 일반 퇴장으로 단정하지 않습니다.
