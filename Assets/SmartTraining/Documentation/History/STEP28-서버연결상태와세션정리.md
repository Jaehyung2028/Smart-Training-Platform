# STEP28 — 서버 연결 상태 표시와 세션 정리

로비 화면과 방 화면 위에 서버 알림 연결 상태를 표시합니다. 이는 ASP.NET SignalR 알림 연결의 상태이며, Unity Netcode 방 접속 상태와 구분합니다.

## 구현 위치

- `ApiLobbyScreen.ConnectionStatus.cs`의 `DrawServerConnectionStatus()`, `ServerConnectionStatusText()` — 로그인 전·연결 중·연결됨·재시도 대기·인증 세션 종료 표시.
- `ScheduleLiveRetry()` — 연결 실패 원인과 재시도 횟수 표시, 3초 후 자동 재시도.
- `RetryLiveConnection()` — `지금 다시 연결` 버튼에서 즉시 재시도.
- `EndServerSession()` — 인증 세션이 무효화되면 이전 방 연결·참가자 목록·채팅·비밀번호 입력·방장 편집창·재접속 대상 정리 및 다시 로그인 안내.
- `ConnectLobbyRooms()`, `RefreshLiveRooms()` — 알림 연결과 REST 조회 결과를 상태 표시에 반영.

## 동작

- 일시적으로 알림 연결만 끊기면 로그인과 Unity Netcode 연결을 유지하고 다시 연결합니다. 현재 방의 채팅 표시도 유지합니다.
- 연결 복구 중에는 방·참가자 목록이 마지막 조회 정보일 수 있다는 안내와 실패 원인, 다음 재시도까지 남은 시간을 표시합니다.
- 재연결 후 참가자·방 목록을 다시 조회하고 방 채팅 연결을 재등록합니다. 성공하면 재시도 횟수를 초기화합니다.
- ASP.NET 서버의 인증 세션이 사라지거나 인증 요청이 거절되면 이전 정보를 정리하고 다시 로그인하도록 안내합니다. 자동 로그인이나 이전 방 자동 입장은 수행하지 않습니다.
- 명시적으로 로그아웃했을 때는 일반 로그인 전 상태로 돌아오며 인증 실패로 표시하지 않습니다.
- 서버 연결 감지는 WebSocket 종료/전송 오류와 REST 요청 실패를 사용합니다. 서버 무응답을 즉시 판정하지는 않으며 네트워크와 기존 요청 제한 시간에 따라 감지가 지연될 수 있습니다.

## 직접 확인

1. Unity 에디터 또는 클라이언트로 로그인하고 위쪽의 `서버 알림 연결: 연결됨` 표시를 확인합니다.
2. 로비 또는 방 접속 상태에서 ASP.NET 서버를 종료합니다. 연결 끊김·재시도 안내가 나타나는지 확인합니다.
3. ASP.NET 서버를 다시 실행합니다. 기존 인증 정보가 무효하면 `서버 인증 세션 종료 — 다시 로그인해주세요`가 표시되는지 확인합니다.
4. 이전 참가자·방·채팅·재접속 대상이 지워졌는지 확인하고 다시 로그인합니다.
5. 새 로그인 후 알림 연결이 복구되고 이전 방에 임의로 입장하지 않는지 확인합니다.
6. 정상 로그아웃 시에는 인증 실패 안내 대신 로그인 전 표시로 바뀌는지 확인합니다.

자동 검증: Unity `Editor/ServerConnectionChecks.cs`에서 실제 인증·알림·Netcode 연결, 일시적인 알림 연결 끊김, 즉시 재연결, 별도 클라이언트의 세션 폐기, 새 로그인 및 정상 로그아웃을 검증합니다. 서버 프로세스 자체의 중지·재실행을 이 테스트에서 수행하지는 않습니다.
