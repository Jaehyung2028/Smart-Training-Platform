# STEP24 — 로비 채팅

현재 입장한 로비의 사용자끼리 ASP.NET SignalR로 채팅합니다. 방에 접속한 상태에서도 같은 로비의 채팅을 사용하며, 플레이어 동기화는 기존 Unity Netcode를 사용합니다.

## 구현 위치

- 서버 `LobbyUpdatesHub.SendChat()` — 인증된 로비 연결의 메시지 전송.
- 서버 `LobbyRoomUpdates.PrepareChat()` — 송신자·수신자 소속/토큰 검증, 메시지 검증, 사용자별 전송 제한, 서버 닉네임·시간 생성.
- Unity `ApiLobbyScreen.Chat.cs`의 `DrawLobbyChat()`, `SendLobbyChat()`, `ReceiveLobbyChat()` — 화면 표시, 전송 결과, 수신 처리.
- Unity `SyncChatLobby()`, `ClearChat()` 및 `DisposeLobbyUpdates()` — 로비 이동/퇴장/로그아웃 연결과 표시 정리.
- `RoomHubConnection.LobbyChat` — 기존 로비 자동 갱신 연결에서 채팅 메시지 수신.

## 규칙

- 메시지 앞뒤 공백을 제거한 뒤 1~200자. 줄바꿈·제어 문자 불가.
- 사용자당 1초에 한 번. 연결을 다시 만들어도 제한은 사용자 기준으로 적용.
- 로그인만 했거나 다른 로비 소속이면 송수신 불가. 토큰 만료·갱신 및 퇴장도 매 전송에서 재검증.
- 최근 수신 100개만 클라이언트 메모리에 표시. 서버 채팅 기록 저장·접속 전 기록 조회·재연결 중 누락 메시지 복구는 미구현.
- 로비를 떠나거나 로그아웃하면 목록과 입력을 삭제. 같은 로비의 연결만 일시 재연결되면 기존 표시를 유지.
- 닉네임·사용자 ID·전송 시각은 서버가 생성. 입력 내용의 서식 태그는 그대로 글자로 표시.
- 전송 실패 시 입력을 유지하고 오류를 표시. 결과가 불확실하면 자동 재전송하지 않음.

## 직접 확인

1. ASP.NET 서버를 재시작하고 Unity 에디터와 클라이언트 빌드를 실행합니다.
2. 서로 다른 닉네임으로 로그인한 뒤 같은 로비에 입장합니다.
3. 화면 아래 `현재 로비 채팅`에 한글 메시지를 전송합니다. 양쪽에 닉네임·시각·내용이 한 번씩 표시되는지 확인합니다.
4. 연속 전송하면 제한 안내와 입력 유지 여부를 확인합니다.
5. 다른 로비에서는 기존 로비의 메시지가 보이지 않는지 확인합니다.
6. 다른 로비 목록을 살펴봐도 채팅은 현재 소속 로비로 유지되는지 확인합니다.
7. 로비 퇴장·로그아웃 후 이전 메시지와 입력이 사라지는지 확인합니다.

자동 검증은 `Tests/Checks/LobbyChatChecks.cs` 및 Unity `Editor/LobbyChatChecks.cs`에 포함됩니다.
