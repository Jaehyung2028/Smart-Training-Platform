# STEP20: 방장 방 닫기

## 추가 함수
- ASP.NET `RoomService.CloseRoomAsync`: 실제 접속 중인 현재 방장만 허용합니다. 새 입장을 차단하고 예약·참가자 방 소속을 정리합니다. 전용 서버에 종료 알림을 보낸 뒤 방과 프로세스를 정리합니다. 알림 전송 실패 시에도 정리는 완료합니다.
- ASP.NET `RoomController.CloseRoom`: 인증된 사용자 ID로 `POST /api/Room/close`를 처리합니다. 요청은 `lobbyId`, `roomId`입니다.
- Unity `TrainingApiClient.CloseRoom` / `ApiLobbyScreen.CloseRoom`: 방장용 닫기 버튼에서 서버 요청 후 로비 화면으로 복귀합니다.
- Unity `RoomDedicatedServer.CloseByMaster`: 참가자에게 “방장이 방을 닫았습니다.”라는 접속 종료 이유를 전달하고 정상 종료합니다.
- Unity `ApiLobbyScreen.HandleConnectionLost`: 방 닫기 종료 이유는 재접속 대상으로 저장하지 않습니다.

## 확인
1. 서버를 재시작하고 새 전용 방 서버 실행 파일을 사용합니다.
2. 두 클라이언트로 같은 방에 들어갑니다. 일반 참가자에게는 닫기 버튼이 보이지 않아야 합니다.
3. 방장이 **방 닫기 — 참가자 전원 로비로 이동**을 누릅니다. 진행 중에도 사용할 수 있습니다.
4. 두 사용자 모두 로그인과 현재 로비를 유지한 채 로비 화면으로 돌아와야 합니다.
5. 참가자는 방장이 방을 닫았다는 메시지를 확인할 수 있어야 하며 재접속 버튼은 없어야 합니다.
6. 방 목록에서 해당 방이 사라지고 로비 목록의 방 개수도 자동 감소해야 합니다.

닫기를 승인한 뒤에는 해당 방으로 다시 입장할 수 없습니다. 필요한 경우 새 방을 생성합니다. 전용 서버 통신 장애 시 종료 이유 전달은 실패할 수 있지만 서버 소속·예약·방·프로세스 정리는 수행됩니다.

## 검증
서버는 일반 참가자·예약 참가자 권한 거절, 잘못된 로비 거절, 닫기 중 입장·중복 요청 거절, 늦은 예약 확인 거절, 알림 실패 시 정리, 진행·방장 상태 초기화를 검증합니다.
Unity 통합 검증은 진행 중 방 닫기, 두 참가자의 로그인·로비 유지, 종료 이유 표시, 재접속 대상 제거, 모든 Netcode 연결 종료 및 목록 삭제를 확인합니다.
