# STEP21: 비밀번호 방

## 변경 함수와 필드
- 서버 `RoomPassword.Valid` / `Set` / `Matches`: 선택적 비밀번호는 4~32자로 검사합니다. 원문을 저장하지 않고 방별 난수와 PBKDF2-SHA256 해시로 저장하며 비교 시 고정 시간 비교를 사용합니다.
- 서버 `RoomService.CreateRoomCore`: 비밀번호를 검사하고 해시를 설정합니다.
- 서버 `RoomService.JoinRoom`: 새 접속 예약 전에 비밀번호를 확인합니다. 생성자도 비밀번호를 입력해야 합니다.
- 서버 `RoomSummaryResponse.HasPassword`: 방 목록·상세는 보호 여부만 표시합니다. 원문·해시·난수는 조회·생성 응답에 포함하지 않습니다.
- Unity `TrainingApiClient.CreateRoom` / `JoinRoom`: 비밀번호를 선택적 요청 인자로 전달합니다.
- Unity `ApiLobbyScreen.CreateRoom` / `JoinRoom` / `ReconnectRoom`: 생성·입장·재접속 입력란을 연결합니다. 입력은 가리고 예약 성공 후 입장 입력을 비우며, 재접속 성공 후 재접속 입력도 비웁니다.

## 확인 순서
1. ASP.NET을 재시작하고 Unity 플레이도 다시 시작합니다.
2. 새 방 비밀번호를 비워 생성하면 기존 공개 방처럼 입장할 수 있어야 합니다.
3. 비밀번호를 입력해 방을 생성하면 방 목록에 `[비밀번호]` 표시가 나타납니다.
4. 방을 선택하면 입장 비밀번호 입력란이 표시됩니다. 빈 입력·틀린 입력은 거절되고 예약 인원이 증가하지 않아야 합니다.
5. 올바른 비밀번호를 입력하면 정상 입장해야 합니다. 대소문자와 공백은 입력 그대로 비교합니다.
6. 연결이 끊긴 뒤 이전 방 재접속 입력란에 비밀번호를 다시 입력합니다. 기존 로그인이나 이전 예약만으로 비밀번호 검사를 건너뛸 수 없습니다.

비밀번호는 생성할 때 설정하며 이번 단계에는 변경·해제 기능을 추가하지 않았습니다. 입장 잠금·진행 상태·정원 제한도 기존대로 적용됩니다. 전용 방 서버 재시작은 비밀번호를 유지합니다. ASP.NET 자체의 전체 데이터를 보관하는 기능은 아직 없으므로 ASP.NET 재시작 시 방 정보도 초기화됩니다.

## 검증
서버 검증은 유효성, 개별 난수 해시, 공개 방 호환, 비밀 정보 제외, 잘못된 비밀번호의 부작용 없음, 정상 예약·확정, 서버 종료 후 보호 유지를 확인합니다.
Unity 통합 검증은 보호 표시, 생성자도 비밀번호 필요, 올바른 비밀번호로 두 클라이언트 입장, 비밀번호 없는 재접속 거절, 재입력 후 새 플레이어로 재접속 및 입력 초기화를 확인합니다. 기존 진행 상태·강퇴·로비 자동 갱신·방 닫기 검증도 함께 실행합니다.
