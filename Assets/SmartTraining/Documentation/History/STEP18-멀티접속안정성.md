# STEP18: 멀티 접속 안정성 점검

## 수정 함수
- ASP.NET `RoomService.SetRoomPhase`: 현재 상태 버전과 요청 버전이 일치할 때만 상태를 변경합니다. 늦게 도착한 이전 요청은 거절합니다. 누락된 사용자 ID도 예외 없이 거절합니다.
- ASP.NET `RoomHub.SetRoomPhase`: 상태 버전을 검사해 서비스에 전달합니다.
- Unity `RoomDedicatedServer.ChangeRoomPhase`: 확인한 상태 버전을 함께 보냅니다.

서버와 Unity 전용 방 서버의 통신 인자가 변경되어 둘을 함께 업데이트해야 합니다. ASP.NET을 재시작하고 새 전용 서버 실행 파일을 사용하세요.

## 직접 확인
1. 두 클라이언트로 같은 방에 입장하고 모두 준비 후 방장이 시작합니다.
2. 방장 클라이언트의 플레이를 종료합니다. 남은 참가자는 연결을 유지하고 새 방장이 되며, 방은 진행 중을 유지해야 합니다.
3. 이전 방장은 진행 중 방에 재접속할 수 없어야 합니다.
4. 새 방장이 대기 복귀 후 이전 방장을 다시 입장시킵니다. 준비 상태는 초기화되고 현재 방장 권한은 유지되어야 합니다.
5. 참가자를 강퇴한 뒤 다시 입장시킵니다. 참가자 수가 중복되지 않고 이전 연결 종료 알림이 새 접속을 지우지 않아야 합니다.
6. 테스트용 전용 방 서버를 종료합니다. 접속·예약·방장·진행 상태가 정리되고 로그인과 로비는 유지되는지 확인합니다.

## 자동 검증 범위
- 서버: 진행 중 방장 연결 종료, 이전 방장 명령 거절, 오래된 상태 버전 거절, 새 입장 토큰 이후 이전 종료 알림 거절.
- 서버 프로세스 테스트: 종료 감지, 접속·예약 정리, 진행 상태·방장 초기화, 이전 서버 알림 거절. 종료 시나리오는 프로세스 관리자 테스트 대역과 별도의 실제 자식 프로세스 종료 테스트로 검증합니다.
- 실제 Unity 전용 서버와 클라이언트: 진행 중 방장 연결 종료, 생존 참가자 연결 유지·자동 위임, 진행 중 재접속 거절, 대기 복귀 후 재접속 및 준비 초기화. 기존 강퇴·재접속·준비·방 설정 검증도 함께 실행합니다.
