# STEP22: 방장 비밀번호 설정·변경·해제

## 변경 함수
- 서버 `RoomService.UpdateRoomPassword`: 현재 접속한 방장만 허용합니다. 새 해시 설정 또는 보호 해제와 미사용 예약 취소를 동일한 잠금 안에서 처리합니다. 이미 접속한 사용자와 확정된 접속 토큰은 유지합니다.
- 서버 `RoomController.UpdateRoomPassword`: `POST /api/Room/password`를 처리합니다. 요청은 `lobbyId`, `roomId`, `password`입니다. 비밀번호 누락·null은 거절하며 빈 문자열은 명시적인 해제입니다.
- 서버 `RoomPassword.Set`: 해제 시 기존 해시와 난수값도 제거합니다.
- Unity `TrainingApiClient.UpdateRoomPassword` / `ApiLobbyScreen.UpdateRoomPassword`: 방장 입력란과 설정·변경 및 해제 버튼을 연결합니다. 성공 후 입력을 비우고 최신 방 목록을 조회합니다.

## 확인
1. 서버와 Unity 플레이를 다시 시작하고 두 참가자가 같은 방에 입장합니다.
2. 방장 화면의 새 비밀번호 입력란에 4~32자로 입력하고 **비밀번호 설정·변경**을 누릅니다.
3. 이미 접속한 두 플레이어는 연결을 유지해야 합니다. 기존 비밀번호로 새 입장은 거절하고 새 비밀번호로는 허용해야 합니다.
4. 변경 전에 예약만 받은 사용자의 예약은 취소됩니다. 그 예약 토큰으로 전용 서버에 들어갈 수 없어야 합니다.
5. **비밀번호 해제 — 공개 방으로 변경**을 누르면 다른 화면의 `[비밀번호]` 표시가 자동으로 사라지고 새 입장에 비밀번호가 필요 없어야 합니다.
6. 공개 방에 다시 비밀번호를 설정하면 표시가 돌아와야 합니다.
7. 방장을 위임하면 새 방장만 변경할 수 있어야 합니다.

진행 중에도 비밀번호를 변경·해제할 수 있습니다. 진행 상태·입장 잠금·정원은 별개이며 그대로 적용됩니다. 같은 비밀번호를 다시 적용해도 미사용 예약은 취소합니다. 해제할 때도 미사용 예약은 취소하며, 새 예약을 받아 입장해야 합니다.

## 검증
서버는 권한, 잘못된 입력 시 기존 비밀번호·예약 유지, 늦은 예약 확인 거절, 확정 토큰 유지, 변경된 비밀번호 검사, 위임 후 권한 변경, 해제 시 비밀값 제거 및 진행 상태·입장 잠금 유지를 확인합니다.
Unity는 API 권한 검사, 실제 전용 서버의 이전 예약 거절, 새 비밀번호 예약, 해제 후 비밀번호 없는 예약, 다른 화면 보호 표시 자동 갱신 및 기존 플레이어 연결 유지를 확인합니다.
