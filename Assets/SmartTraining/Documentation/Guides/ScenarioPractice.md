# 시나리오 실습

안전 교육 과정의 공구 체결 실습 항목에서 방을 만들고 참가자 준비 후 시작합니다.
예시 단계 원본은 Content/Scenarios/ToolAssembly.asset이며 현재 목표는 볼트 풀기·체결 → 나사 풀기·체결 → 핀 타격 → 공구 없이 결과 확인의 6단계입니다.

1. 오른쪽 아래 ‘기능 메뉴’를 열고 ‘공구 선택 (개인)’의 스패너·드라이버·망치 버튼 중 하나를 선택합니다. 버튼에 공구 이름과 선택됨 표시를 함께 표시합니다.
2. WASD로 작업대에 접근하고 우클릭 드래그로 시점을 조절합니다.
3. 공구가 필요한 목표는 자신이 맞는 공구를 고른 뒤 대상 클릭으로 완료합니다. ToolId가 빈 목표는 공구 선택 없이 대상만 클릭하면 완료합니다.

공구 선택은 개인 상태입니다. 다른 사람이 스패너를 골라도 나에게 적용되지 않습니다.
공구가 필요한 목표에서만 공구 미선택·오답을 검사합니다. 공구가 없는 목표에서는 어떤 공구를 선택해 두었든 공구 검사를 생략하고 기존 선택도 유지합니다.
공구 선택은 목표 완료 수를 늘리지 않습니다. 목표가 하나라면 맞는 공구로 대상 작업 시 전체 완료입니다.
같은 공구는 다음 단계에서도 개인 선택 상태를 유지합니다. 기능 메뉴의 ‘선택 안 함’ 버튼으로 해제할 수 있습니다. 공구를 눌러도 기능 메뉴는 자동으로 닫히지 않습니다.
기존 예시의 3D 스패너 선택 오브젝트는 제거했으며, 공구를 3D 공간에서 고르지 않습니다.

완료 단계와 최근 작업자는 참가자 모두에게 공유합니다. 현재 대상은 노란색, 완료 대상은 초록색입니다.
방장은 기능 메뉴에서 초기화할 수 있고 초기화·새 실습 시작 시 모든 개인 공구도 해제합니다.
접속 종료 시 해당 참가자의 선택만 서버에서 제거합니다. 개인 성적 저장은 포함하지 않습니다.

## 역할과 판정

| 스크립트 | 역할 |
|---|---|
| ScenarioDefinition | Tools 메뉴 목록과 Steps 작업 목표 원본 |
| ScenarioObject | 작업 대상의 ID |
| ScenarioProgress | 참가자별 공구와 공동 목표 규칙 |
| SharedScenario | 실제 송신자의 공구 선택·거리·방장 검사, 목표 동기화 |
| ScenarioProgressState | 공동 단계·초기화 번호·최근 작업자만 공개 |
| ScenarioServerSession | ASP.NET이 확정한 assetId로 원본 로드·해제 |
| ScenarioContent | 로컬 메뉴 요청·모델 클릭 연결 |
| ScenarioObjectView | 대상 색상·볼트 풀기 표현 |
| ScenarioControlPanel | 공동 진행 안내와 내 선택 공구 표시 |
| ScenarioToolMenu | 기능 메뉴 안의 개인 공구 버튼 목록 |

서버는 연결 ID별 선택 공구를 판정하고 표시용 선택 목록을 모든 참가자에게 공유합니다. 다른 사람의 선택을 본인의 공구로 사용하지는 않습니다.
모델 클릭 요청에는 대상 ID와 단계 버전만 보내며 사용자 ID·선택 공구를 임의로 붙여 보내지 않습니다.
서버가 실제 송신자의 선택을 조회해 판정합니다. 목표 진행은 NetworkVariable로, 공구 표시용 목록은 NetworkList로 공유합니다.
메뉴 선택은 공동 단계 버전을 변경하지 않아 다른 사용자의 공구 선택을 무효화하지 않습니다.
초기화 번호를 별도로 검사해 이전 실습의 늦은 선택 요청이 새 실습에 적용되지 않게 합니다.

## 데이터 작성

ToolAssembly.asset의 Tools에 공구 Id와 Title을 등록합니다. 정답뿐 아니라 오답 공구도 등록할 수 있습니다.
각 Step의 ToolId를 비워 두면 공구 불필요입니다. ToolId를 입력한다면 Tools의 Id와 같아야 합니다. 모든 목표가 공구 불필요라면 Tools 목록도 비워 둘 수 있습니다. TargetId는 항상 프리팹 내 작업 대상 ScenarioObject.Id와 같아야 합니다.
공구용 3D 오브젝트는 필요하지 않습니다. 작업 대상에는 Collider와 ScenarioObject(Target)를 연결합니다.
ID는 중복 없이 UTF-8 60바이트 이내로 작성합니다. ScriptableObject에는 실행 중 상태를 저장하지 않습니다.
카탈로그의 contentType은 scenario, assetId는 해당 Addressables 프리팹 주소로 지정합니다.
서버와 클라이언트 모두 최신 Addressables로 빌드합니다.

## 잘못된 선택 안내

공구가 필요한 목표의 미선택: ‘공구를 먼저 선택해주세요.’
잘못된 공구로 맞는 대상 클릭: ‘공구를 잘못 선택했습니다.’
다른 볼트·작업대처럼 잘못된 오브젝트 클릭: ‘오브젝트를 잘못 선택했습니다.’
공구와 대상이 둘 다 틀리면 오브젝트 안내를 먼저 표시합니다.
실패한 요청은 목표를 진행하지 않으며 화면 하단 알림을 약 4초 표시합니다. 같은 실수를 반복해도 알림이 다시 표시됩니다.

## 기존 실습 안의 공구 없는 확인 단계

‘공구별 체결·타격 실습’은 스패너의 볼트 풀기·체결 → 드라이버의 나사 풀기·체결 → 망치의 핀 고정 → 공구 없이 결과 확인 순서입니다. 풀기와 체결은 각각 1.5초이며, 서버가 완료를 확정하기 전에는 다음 단계로 넘어가지 않습니다. 모든 참가자는 공유된 시작 시각으로 같은 회전·분리 동작을 표시합니다. 초기화하면 작업과 개인 공구 선택을 취소하고 원래 자세로 돌아갑니다.
마지막 목표의 ToolId만 비어 있습니다. 공구를 선택하지 않은 참가자도 완료할 수 있고, 이미 공구를 선택했다면 따로 해제할 필요가 없습니다.
원본은 Content/Scenarios/ToolAssembly.asset이며 기존 Addressables 주소 content/scenario/tool-assembly를 사용합니다.

왼쪽 카드는 제목·공동 진행률·현재 목표·필요 공구 조건·단계 목록을 구분합니다.
현재 단계는 파란 배경, 완료 단계는 초록 글씨, 대기 단계는 회색으로 표시하고 긴 목록은 스크롤할 수 있습니다.
공구 없는 확인 목표는 색상으로 완료만 표시하며 볼트 회전 연출은 추가하지 않습니다.

### 작업 진행과 취소

작업 중 카드 아래에 작업자·진행률 막대와 작업 취소 버튼을 표시합니다. 실제 작업자에게만 취소 버튼이 활성화되며, 서버도 RPC 송신자의 연결 ID와 현재 작업 버전을 다시 확인합니다. 방장도 다른 참가자의 작업을 개별 취소할 수 없고 기존 전체 초기화 권한은 유지합니다.

취소는 완료한 단계와 개인 공구 선택을 보존합니다. 풀기를 취소하면 원래 자세로, 체결을 취소하면 풀려 있던 자세로 모든 참가자의 모델을 되돌립니다. 취소 후 같은 단계를 다시 시작할 수 있고 이전 작업의 취소 요청은 재시작한 작업에 적용되지 않습니다. 서버의 작업 완료 시각 이후 도착한 취소는 거절합니다. 이미 승인한 작업은 작업자가 접속을 끊어도 기존처럼 완료됩니다.

### 손에 드는 공구

선택한 공구 ID는 서버가 참가자별로 판정한 뒤 Netcode NetworkList로 공유합니다. 공구 모델을 별도 NetworkObject로 생성하거나 매 프레임 RPC로 전송하지 않습니다. 본인의 손은 1인칭 카메라를, 다른 참가자의 손은 해당 캐릭터를 따라갑니다. 선택 안 함·전체 초기화·대기 복귀·접속 종료 시 해당 표시를 정리합니다. 작업 취소는 선택 공구를 유지합니다.

샘플 손과 공구는 Content/Scenarios/Tools의 RightHand·spanner·screwdriver·hammer 프리팹입니다. ScenarioDefinition의 Tools > Held Prefab에서 실제 모델로 교체할 수 있습니다. 프리팹 원점이 손의 Grip에 해당하며 공구에는 NetworkObject가 필요하지 않습니다. 공통 HeldItemView는 프리팹 표시만 담당하고 ScenarioEquipmentView가 참가자·카메라 연결을 담당합니다.

### 스패너 작업 동작

서버 작업 시간의 처음 20%는 손 접근, 중간 60%는 볼트 회전, 마지막 20%는 손 복귀에 사용합니다. ScenarioWorkMotion의 공통 진행 곡선을 볼트와 손이 함께 사용합니다. 작업 중 스패너의 접촉점이 볼트 Work Anchor를 따라가며, 취소하면 짧게 손 위치로 복귀합니다. 별도 매 프레임 RPC나 손 위치 전송은 사용하지 않습니다.

ScenarioDefinition의 Tools에는 Animate Work·Work Contact Point·Work Rotation이 있고, 대상 ScenarioObject에는 Work Anchor가 있습니다. 기본 예시의 스패너·드라이버·망치에 작업 동작을 설정했습니다. 실제 공구 모델로 교체하면 해당 모델의 로컬 접촉점과 작업 방향을 조정합니다. 손 모델 표시와 접촉점 계산은 공통 HeldItemView, 시나리오 작업 연결은 ScenarioEquipmentView가 담당합니다.

작업자 본인은 작업 중 공구를 변경할 수 없고 취소 후 다시 선택할 수 있습니다. 다른 참가자는 자신의 공구를 계속 선택할 수 있습니다.

### 공구별 6단계 실습

기본 ToolAssembly 예시는 스패너로 볼트 풀기·체결, 드라이버로 나사 풀기·체결, 망치로 핀 고정, 공구 없이 결과 확인 순서입니다. 공구 선택은 참가자별이며 각 단계의 Tool Id·Target Id를 서버에서 검사합니다. 나사는 screw-a, 핀은 pin-a입니다.

Strike 작업은 가운데 작업 구간에 세 번 들어 올리고 내려칩니다. 각 타격 시점에 핀이 1/3씩 들어가며, 손이 복귀하고 서버 작업 시간이 끝난 뒤 단계가 완료됩니다. 타격 중 취소하면 핀을 작업 전 상태로 되돌리고 같은 단계에서 재시작합니다. 나사 회전과 타격은 모두 기존 서버 시계를 사용합니다.

### 실습 결과

최종 확인을 마치면 모든 참가자에게 현재 실습의 결과 화면이 표시됩니다. 서버 실습 시작부터 최종 완료까지의 소요 시간, 단계별 완료 수행자와 단계 소요 시간, 공구·대상 오류 합계를 표시합니다. 완료 후 시간과 결과는 고정됩니다.

공구 미선택·오선택 또는 잘못된 대상을 클릭해 작업을 시도했을 때 서버가 오류를 집계합니다. 메뉴에서 공구를 바꾸는 행동 자체는 집계하지 않으며, 오래된 요청·작업 중 중복 요청·거리 부족은 제외합니다. 단계별 오류는 수행자 한 명이 아니라 해당 단계 전체 참가자의 합계입니다. 취소한 작업은 완료 수행자로 기록하지 않습니다.

결과 화면에서는 방장만 다시 실습하거나 대기실로 복귀할 수 있습니다. 다시 실습하면 시간·수행자·오류가 모두 초기화됩니다. 현재 실습의 메모리 기록이며 대기 복귀·콘텐츠 변경·방 종료 이후에는 결과를 보관하지 않습니다. 결과 기록은 ScenarioRunResults, 네트워크 전달은 SharedScenario·ScenarioStepOutcome, 결과 화면은 ScenarioResultPanel이 담당합니다.
