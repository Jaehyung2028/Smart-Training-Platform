# 콘텐츠 Addressables 구성

콘텐츠 시작 시 `catalog.json`의 `assetId`와 같은 Address를 가진 **GameObject 프리팹**을 불러옵니다.
`video`, `model`, `scenario` 모두 기본 진입 리소스는 프리팹입니다.

| 타입 | 기본 프리팹 구성 예시 |
|---|---|
| video | 재생 화면, VideoPlayer, 기본 영상 참조 |
| model | 관찰할 3D 모델과 기준점 |
| scenario | 작업 환경, 공구 배치, 실습 진행 스크립트 |

## 기본 프리팹 등록

1. Unity의 `Smart Training > Prepare Addressable Content`를 실행합니다.
2. `Window > Asset Management > Addressables > Groups`에서 콘텐츠 프리팹을 등록합니다.
3. Address를 `content/model/electric-drill`처럼 지정합니다.
4. 서버 카탈로그의 해당 최하위 노드에 같은 `assetId`를 입력하고 서버를 재시작합니다.

```json
{
  "id": 2,
  "title": "전동 드릴 관찰",
  "contentType": "model",
  "assetId": "content/model/electric-drill",
  "children": []
}
```

분류용 `category`에는 `assetId`를 지정하지 않습니다.
최하위 항목의 빈 `assetId`는 제작 중 상태이며 공통 콘텐츠 씬에서 미등록 안내를 표시합니다.
동일 프리팹을 사용하는 항목은 같은 Address를 공유할 수 있습니다.

## 추가 리소스 불러오기

기본 프리팹의 부모에는 `ContentResourceContext`가 생성됩니다.
콘텐츠 스크립트의 `Start()` 이후 `GetComponentInParent<ContentResourceContext>()`로 접근합니다.
이 컨텍스트는 프리팹의 `Awake()` 이전에 부모에 준비됩니다.

- `LoadAdditional<T>()`: VideoClip, Material 등 추가 에셋 로드
- `InstantiateAdditional()`: 추가 공구·오브젝트 프리팹 로드 및 생성

```csharp
private IEnumerator Start()
{
    var resources = GetComponentInParent<ContentResourceContext>();
    yield return resources.InstantiateAdditional(
        "content/tool/electric-drill",
        transform,
        instance => Debug.Log("추가 공구 생성 완료"),
        message => Debug.LogWarning(message)
    );
}
```

이 경로에서 로드한 에셋은 콘텐츠 실행 범위가 소유합니다.
대기 복귀·퇴장 시 기본 프리팹과 추가 인스턴스를 제거하고 로드 핸들을 반환합니다.
미완료 로드도 정리 대상으로 등록하므로 종료 후 콜백이 오브젝트를 다시 생성하지 않습니다.
추가 로딩을 반복하면 사용한 리소스는 해당 콘텐츠가 끝날 때까지 유지됩니다.

리소스 로딩과 멀티플레이 상태는 분리합니다. 공유 모델 조작은 SharedModel, 영상 재생 시계는 SharedVideo, 시나리오 공동 진행은 SharedScenario가 담당합니다.
이 로더는 각 클라이언트에 표시할 리소스의 생성·해제만 담당합니다.
Addressables로 스크립트 코드를 새로 배포할 수는 없으므로 필요한 스크립트는 클라이언트 빌드에 포함해야 합니다.

## 빌드

실제 실행 파일에서는 등록한 에셋의 Addressables 콘텐츠도 빌드해야 합니다.
Groups 창의 콘텐츠 빌드 설정과 플레이어 빌드 시 Addressables 빌드 옵션을 확인합니다.
원격 배포를 사용할 경우 호스팅 주소와 카탈로그 업데이트 정책은 별도로 설정합니다.

## 3D 모델 둘러보기

`테스트 훈련 콘텐츠 > 기본 훈련 단계`는 `content/model/training-drill` 프리팹을 사용합니다.
`Smart Training > Content > Prepare Model Viewer Example`으로 예시 프리팹과 Addressables 등록을 준비할 수 있습니다.
기존 예시 프리팹이나 재질이 있으면 덮어쓰지 않습니다.

- WASD: 캐릭터 이동
- 마우스 오른쪽 드래그: 1인칭 시점 회전
- Esc 또는 `메뉴`: 설정·대기 복귀·방 나가기

모델 콘텐츠도 공통 3D 공간에서 진행합니다. 바닥과 다른 참가자의 캐릭터가 표시되며, 이동은 기존 서버 권한 Netcode 경로로 동기화합니다.
모델은 Addressables 프리팹에 지정한 위치·크기로 표시합니다. 예시 드릴은 공간 중앙에 있으며 참가자가 직접 가까이 가거나 주변으로 이동해 관찰합니다.
모델 콘텐츠 시작 시 전용 서버가 `SharedModel` 네트워크 프리팹을 한 개 스폰합니다. 각 클라이언트는 Addressables 모델을 그 루트의 자식으로 표시합니다.
루트의 `NetworkTransform`은 `Authority Mode = Owner`이며 회전만 동기화합니다. 위치와 크기는 고정합니다.
평소에는 서버가 소유하고, 모델을 6m 이내에서 왼쪽 드래그하면 서버가 조작자를 확인한 뒤 소유권을 넘깁니다.
조작 중 회전은 소유자가 현재 카메라 방향을 기준으로 직접 적용하며, 회전 전송·다른 참가자의 보간은 NetworkTransform이 담당합니다.
다른 사람이 이미 소유한 동안에는 조작권을 빼앗을 수 없습니다. 버튼을 놓거나 UI·메뉴로 이동하면 반환을 요청합니다.
접속 종료·거리 이탈·대기 전환·30초 무회전 시 서버가 권한을 회수합니다. 대기 복귀 시 네트워크 모델은 제거되고 다음 시작 때 새로 생성됩니다.
RPC는 조작 시작·종료에만 사용합니다. 종료 요청에는 마지막 회전도 한 번 포함해 패킷 도착 순서에 따른 마지막 각도 유실을 방지합니다.
휠 버튼을 누르는 동안 내 1인칭 카메라 화각이 25% 좁아지며, 놓으면 부드럽게 복귀합니다. 확대는 개인 화면에만 적용됩니다.

실제 모델로 교체하려면 MeshRenderer 또는 SkinnedMeshRenderer가 포함된 GameObject 프리팹을 Addressables에 등록하고 해당 `assetId`를 지정합니다.
ModelViewer는 표시 가능한 메시를 검사하고 모델 클릭·회전을 처리합니다. 카메라 확대와 캐릭터 이동은 ContentSceneSession이 담당합니다.

### 콘텐츠 기능 메뉴

화면 오른쪽 아래의 `기능 메뉴`를 누르면 현재 콘텐츠에 등록된 기능 버튼이 펼쳐집니다. 모델 콘텐츠에는 `회전 초기화`가 등록됩니다.
기능 메뉴를 열어도 캐릭터 이동·시점·모델 드래그·응시를 계속 사용할 수 있습니다. UI 위에서 모델 드래그·응시가 중복 실행되는 것은 막습니다. 다시 버튼을 누르거나 Esc를 누르면 닫힙니다.
설정 메뉴 열기·대기 복귀·퇴장 시에도 기능 메뉴가 닫히며 콘텐츠가 바뀌면 기능 목록을 다시 구성합니다.
회전 초기화는 모델에서 6m 안에 있고 아무도 조작하지 않을 때 사용할 수 있습니다. 서버에서 상태·거리·소유권을 다시 검사하고 모든 참가자에게 초기 회전을 동기화합니다.
위치·크기·개인 응시 배율은 초기화하지 않습니다. 영상 재생 조작과 시나리오 실습 초기화도 같은 콘텐츠 기능 메뉴에 등록합니다.

### 모델 조작자 표시

모델 콘텐츠의 화면 상단에 현재 조작 상태를 표시합니다. 서버가 소유하면 `모델 조작 가능`, 참가자가 소유하면 `닉네임 님이 모델을 조작 중입니다.`를 표시합니다.
내가 조작 중일 때는 초록색, 다른 사람이 조작 중일 때는 노란색입니다. 기존 소유권과 RoomPlayer 닉네임으로 표시하며 추가 네트워크 메시지는 전송하지 않습니다.
조작 종료·소유권 회수 시 자동으로 조작 가능 상태로 돌아옵니다. 대기 복귀·퇴장·다른 유형의 콘텐츠에서는 숨깁니다.

### 부품 마우스 강조

모델에서 6m 안에서 마우스로 가리킨 부품을 청록색으로 강조합니다. 현재는 Renderer 단위로 부품을 구분하며, 정적 메시에는 실제 메시 표면 판정을 사용합니다.
기존 Collider가 있으면 그대로 사용하고, 없으면 클라이언트의 표시용 모델에만 선택용 Collider를 추가합니다. 읽기 불가능한 메시·SkinnedMeshRenderer는 경계 상자를 사용하므로 정밀 판정이 필요하면 전용 Collider를 지정합니다.
강조는 MaterialPropertyBlock으로 개인 화면에만 적용합니다. 공유 재질은 수정하지 않고, 마우스 이탈·UI 위·드래그·메뉴·퇴장 시 기존 슬롯별 설정을 복원합니다.
한 메시로 합쳐진 모델은 전체가 한 부품으로 처리됩니다. 부품별 강조가 필요하면 부품을 별도 Renderer로 구성합니다. 짧은 클릭은 아래 부품 설명 기능으로 연결됩니다.

### 부품 클릭 설명

마우스 왼쪽 버튼으로 부품을 짧게 클릭하면 왼쪽에 이름·설명이 표시됩니다. 8픽셀보다 크게 움직이면 회전 드래그로 구분하고, 이때만 서버에 조작권을 요청합니다.
클릭은 0.35초 이내의 누르기·놓기이며 같은 부품에서 완료되어야 합니다. 빈 공간 클릭 또는 설명 창의 `닫기`로 선택을 해제합니다.
설명은 개인 화면에만 표시되며 다른 사람이 회전 중이어도 부품 정보를 확인할 수 있습니다. 창 위에서는 모델 입력을 차단하지만 창을 열었다고 이동·시점을 멈추지 않습니다.
부품 오브젝트 또는 부품의 부모에 `ModelPartInfo`를 붙이고 Title·Description을 작성합니다. 정보가 없으면 오브젝트 이름과 미등록 안내를 표시합니다.
예시 드릴에는 모터 하우징·손잡이·배터리·받침·스위치·척·비트·통풍구 설명을 추가합니다. 이미 설명이 있으면 빌더가 덮어쓰지 않습니다.
긴 설명은 휠로 스크롤할 수 있으며 대기 복귀·퇴장 시 창과 선택도 정리됩니다.

### 선택 부품 강조 유지

마우스로 가리킨 부품은 청록색, 설명을 연 부품은 주황색으로 표시합니다. 같은 부품을 가리키면 선택 색상이 우선합니다.
다른 부품을 가리킬 때도 기존 선택의 주황색은 유지되고, 새 부품을 클릭하면 선택 강조가 이동합니다.
UI 위·이동·시점 조작·공유 모델 회전 중에도 선택 색상을 유지합니다. 설명 닫기·빈 공간 클릭·퇴장 시 원래 슬롯 설정을 복원합니다.
선택은 개인 화면에만 적용하며 공유 재질이나 네트워크 상태를 수정하지 않습니다.

### 부품 목록

오른쪽 아래 `기능 메뉴 > 부품 목록`을 누르면 오른쪽에 부품 목록이 표시됩니다. 목록에서 선택하면 동일한 부품 설명과 주황색 강조를 적용합니다.
모델에서 직접 클릭해도 목록에 `선택` 표시가 갱신되고, 선택한 행이 보이도록 스크롤합니다. 이름은 ModelPartInfo.Title을 사용하며 같은 이름이 여러 개면 번호로 구분합니다.
목록을 열어도 이동·시점·회전을 중지하지 않으며, 다른 사람이 모델을 조작할 때도 개인별로 부품을 선택할 수 있습니다.
목록 닫기는 현재 선택과 설명을 유지하고, 설명 창 닫기·빈 공간 클릭은 선택을 해제합니다. Esc·설정 메뉴·대기 복귀·퇴장 시 목록을 닫습니다.
콘텐츠를 다시 로드하면 표시 가능한 Renderer를 포함하는 Transform 계층으로 트리를 다시 구성합니다. 목록 선택은 모델 소유권이나 네트워크 상태를 변경하지 않습니다.

### 계층형 부품 선택

목록은 실제 Transform 계층을 들여쓰기로 표시하고 `+`·`-` 버튼으로 가지를 펼치고 접습니다. 표시 가능한 메시가 있는 가지와 그 부모를 포함하며, 빈 보조 오브젝트는 제외합니다.
메시가 없는 부모도 선택할 수 있습니다. 부모 선택 시 해당 노드의 모든 하위 Renderer에 주황색 강조를 적용하고, 선택한 노드의 이름·설명을 표시합니다.
자식을 선택하면 선택 범위가 그 자식의 하위로 바뀝니다. 이전 범위의 색상과 PropertyBlock을 복원하므로 부모·자식 선택이 겹쳐도 강조가 남지 않습니다.
직접 클릭한 메시가 접힌 가지 안에 있으면 부모를 자동으로 펼쳐 선택 행을 표시합니다. 트리를 접는 동작 자체는 선택과 설명을 해제하지 않습니다.
이름은 해당 오브젝트의 ModelPartInfo.Title 또는 오브젝트 이름을 사용합니다. 설명이 없으면 가까운 부모의 설명을 사용합니다. 예시 드릴에는 조립체와 통풍부의 계층을 추가하며 기존 부품의 배치와 설명은 유지합니다.
### 주변 부품 투명도

부품을 선택한 뒤 `기능 메뉴 > 주변 반투명`을 켜면 선택한 부품과 모든 하위 자식은 그대로 두고 나머지만 반투명으로 표시합니다.
`주변 부품 투명도` 슬라이더는 0%(원래 불투명도)~100%(완전 투명)를 조절하며 기본값은 70%입니다. 슬라이더 조절 중에는 메뉴를 유지합니다.
선택 해제·기능 끄기·콘텐츠 종료 시 원래 재질과 PropertyBlock을 복원하고 임시 재질을 해제합니다. 기능이 켜진 상태에서 새 부품을 선택하면 새 선택 범위에 적용합니다.
처리는 개인 화면에만 적용하고 회전 소유권·다른 참가자의 선택과 표시에는 영향을 주지 않습니다. URP Lit/Unlit 계열과 Standard 재질을 지원하며 사용자 정의 셰이더는 별도 투명 처리 지원이 필요합니다.

빌드에서 URP Lit 투명 셰이더 변형이 제거되지 않도록 Resources/SmartTraining/ModelTransparencyVariant.mat를 포함합니다. 화면에 생성하는 모델이 아니라 빌드용 기준 재질입니다. 다른 셰이더를 도입할 때도 해당 투명 변형을 빌드에 포함해야 합니다.

### 애니메이션 기반 공유 분해 보기

모델 프리팹의 `ModelDisassemblyAnimation` 컴포넌트에 분해 AnimationClip을 연결합니다. 같은 오브젝트의 Animator를 사용하며 실제 재생에는 Animator Controller가 필요하지 않습니다. 예시 프리팹에는 Animation 창 편집을 위한 Controller만 연결하고 자동 재생은 꺼 둡니다.
클립의 0초는 조립 상태, 마지막은 분해 상태로 만들고 Loop Time을 끕니다. 자식 부품의 로컬 위치·회전·크기를 키프레임으로 작성합니다. 모델 루트 자체나 재질·활성 상태는 애니메이션하지 않습니다.
Animation 창에서 해당 프리팹을 열어 클립의 분해 순서와 경로를 수정할 수 있습니다. 예시 `TrainingDrillDisassembly.anim`은 배터리 → 비트 → 척 → 외장 순서로 이동하고 손잡이 묶음의 회전도 포함합니다. 빌더는 이미 연결한 클립이나 수정한 키프레임을 덮어쓰지 않습니다.
기능 메뉴의 `분해 보기` 0~100%는 클립의 0초~마지막 시간에 대응합니다. Playables의 수동 평가를 사용해 역방향으로도 같은 포즈를 표시하고, 0%·콘텐츠 종료 시 최초 위치·회전·크기를 복원합니다. 클립이 없으면 슬라이더가 비활성화됩니다.
서버가 시작 진행도·방향·시작 시각·전체 재생 시간을 담은 NetworkVariable 하나를 관리합니다. 각 클라이언트가 서버 시각에 맞춰 같은 클립을 재생하고 모델 전체 회전은 바깥쪽 SharedModel이 담당합니다. 선택·설명·투명도는 개인별로 유지합니다.
슬라이더 요청은 0.1초 간격으로 최신 값만 보내며 서버가 참가 상태·거리·소유권을 검사합니다. 다른 참가자가 모델 회전 조작권을 가진 동안은 분해도를 변경할 수 없습니다.
기능 버튼을 눌러도 메뉴는 자동으로 닫히지 않습니다. 기능 메뉴 버튼·Esc로 직접 닫으며 콘텐츠 종료·대기 복귀 시에는 정리합니다. 부품 목록은 기능 메뉴 왼쪽에 표시합니다.

### 분해 자동 재생·일시정지·재조립

기능 메뉴의 `분해 재생`은 현재 지점에서 끝까지, `재조립`은 현재 지점에서 처음까지 진행합니다. 전체 구간을 재생하는 시간은 연결된 클립의 길이입니다. `일시정지`는 서버가 요청을 받은 시점의 진행도에 고정합니다.
모든 참가자는 같은 재생 상태를 봅니다. 시작·정지·방향 변경·구간 이동·끝 도달 때만 상태를 전송하며 매 프레임 진행도나 RPC를 보내지 않습니다. 재접속 시에도 현재 서버 시각에 해당하는 포즈를 계산합니다.
재생 중 슬라이더를 움직이면 자동 재생을 멈추고 해당 구간으로 이동합니다. 슬라이더 이동 직후 재생 버튼을 누르면 보류 중인 구간 이동을 먼저 처리합니다. 기능 메뉴는 계속 열려 있고, 다른 참가자가 모델 회전 조작권을 가지고 있으면 재생 제어도 제한됩니다.
끝에서는 자동으로 정지하고 해당 방향의 재생 버튼이 비활성화됩니다. 콘텐츠를 대기로 돌렸다가 다시 시작하면 조립 상태·정지 상태부터 시작합니다.

### 분해 단계 안내

모델 프리팹의 `ModelDisassemblyAnimation > Steps`에서 단계별 `Time`(클립 시간, 초), `Title`, `Description`, `Targets`를 설정합니다. Targets에는 부품 또는 부모 묶음을 여러 개 지정할 수 있고 하위 Renderer도 포함됩니다.
시간순으로 정렬해서 사용하고 클립 범위를 벗어난 시간과 같은 시간의 중복 단계는 제외합니다. 첫 단계 전에는 시작 전 안내를 표시하며, 대상이 없거나 삭제되어도 제목·설명은 표시합니다.
분해 재생·일시정지·재조립과 슬라이더로 공유 재생 위치를 조절합니다. 별도의 단계 설명창과 자동 부품 선택은 사용하지 않습니다.
부품은 모델 클릭이나 부품 목록에서 직접 선택합니다. 분해·재조립 중에도 각자의 선택을 유지하며, 주변 투명도는 현재 선택을 제외한 나머지 부품에 적용합니다.
예시 드릴에는 배터리·비트·척·외장·통풍부의 다섯 단계를 연결합니다. 이미 작성한 단계 목록은 빌더가 덮어쓰지 않습니다.

### 비디오 시청 콘텐츠

카탈로그의 최하위 항목에 `contentType: video`, `assetId: content/video/safety-intro`를 지정하면 영상 프리팹을 로드합니다. 예시는 안전 교육 과정의 `작업 전 안전 수칙 영상` 항목입니다.
`Assets/SmartTraining/Content/Videos/SafetyVideo.prefab`의 VideoContentPlayer에서 Clip과 화면 Renderer를 연결합니다. VideoClip은 프리팹의 Addressables 의존성으로 함께 로드되며 서버는 영상 파일을 디코딩하거나 스트리밍하지 않습니다.
영상 화면은 공통 3D 공간에 배치하고 캐릭터로 이동하면서 볼 수 있습니다. 화면 하단에서 재생·일시정지·구간 이동을 조작합니다. 재생·일시정지·구간 이동은 모든 참가자가 조작할 수 있고 서버가 실제 접속자의 RoomPlayer와 진행 상태를 다시 검사합니다. 서버가 처리한 재생 상태는 조작자 포함 모든 참가자에게 공유합니다. 최초 영상 길이 등록만 방장이 담당하며 방장 위임은 재생 상태에 영향을 주지 않습니다.
재생 위치는 시작 시각·위치·길이·재생 여부를 묶어 서버에서 확정합니다. 각 클라이언트가 서버 시각을 기준으로 재생하며 준비가 늦거나 재접속해도 현재 위치로 맞춥니다. 재생 중 0.35초 이상 차이가 나면 보정하고, 정지 상태도 같은 시각으로 맞춥니다. 프레임 단위의 완전 동시 재생을 보장하는 방송 시스템은 아닙니다.
구간 이동과 5초 뒤로·앞으로 버튼은 기존 재생·일시정지 상태를 유지하고, 범위는 0초부터 영상 끝까지로 제한합니다. 5초 이동의 기준 위치는 서버에서 계산하여 연속 요청도 처리 순서대로 반영합니다. 정지 버튼은 위치를 0초로 되돌리고 재생을 멈추는 상태를 한 번에 공유합니다. 끝에서는 자동으로 정지합니다. 끝난 뒤 재생을 누르면 처음부터 시작합니다. 내 영상 음량은 개인별 AudioSource 값이고 다른 참가자의 음량에는 영향을 주지 않습니다. 전체 음량 설정도 함께 적용됩니다.
예시 mp4는 Unity MediaEncoder가 생성하는 12초짜리 영문 안전 안내 영상과 짧은 안내음입니다. 클립과 프리팹이 이미 있으면 빌더는 덮어쓰지 않으므로 실제 교육 영상으로 교체할 수 있습니다.
영상 준비가 실패하거나 30초를 초과하면 화면에 오류를 표시합니다. 대기 복귀·퇴장 시 VideoPlayer를 멈추고 로컬 RenderTexture·재질과 Addressables 핸들을 정리합니다.

### 영상 자막

VideoContentPlayer의 Subtitle File에 UTF-8 SRT 자막을 연결합니다. Unity TextAsset으로 가져올 수 있도록 확장자는 `.srt.txt`를 사용합니다. 예시는 `Content/Videos/SafetyIntro.srt.txt`이며 영상 프리팹의 Addressables 의존성으로 함께 로드됩니다.
각 구간은 번호, `00:00:00,000 --> 00:00:04,000`, 문장, 빈 줄 순서입니다. 여러 줄 문장과 겹치는 구간을 지원합니다. 잘못된 형식은 경고를 표시하고 영상은 자막 없이 계속 재생합니다.
자막은 공통 영상 위치로 표시되므로 재생·일시정지·탐색·정지에 맞춰 바뀌고 초기 준비 상태·정지 버튼으로 복귀한 0초·영상 끝·빈 구간에서는 숨겨집니다. 재생 후 일시정지한 위치에서는 자막을 유지합니다. `자막 켜짐/꺼짐`은 개인 설정이며 다른 참가자의 표시에는 영향을 주지 않습니다. 자막 파일이 없으면 `자막 없음`으로 표시하고 버튼은 비활성화합니다.

### 시나리오 실습 데이터

`contentType: scenario`, `assetId: content/scenario/tool-assembly`로 예시를 로드합니다. 안전 교육 과정의 공구 체결 실습 항목이며, 기본 프리팹은 `Content/Scenarios/ToolAssembly.prefab`, 단계 원본은 `ToolAssembly.asset`입니다.
ScenarioDefinition에는 ID·제목·순서대로 실행할 Steps를 설정합니다. Tools에 메뉴 공구 Id·Title을 등록하고 단계별 ID·Title·Instruction·Tool Id·Target Id를 작성합니다. 각 단계는 지정 대상을 작업하는 목표입니다. Tool Id가 비어 있으면 공구 없이 완료하고, 값이 있으면 해당 공구가 필요합니다. 공구 선택은 준비 행동이며 단계 완료 수를 늘리지 않습니다. 기본 예시는 스패너의 볼트 풀기·체결, 드라이버의 나사 풀기·체결, 망치의 핀 타격과 공구 없는 최종 확인의 6단계입니다. Action을 Check·Loosen·Tighten·Strike 중 선택하고 풀기·체결 작업의 Duration Seconds를 설정합니다. 서버가 작업 시간을 판정하며 작업이 끝난 뒤 다음 단계로 넘어갑니다. ScenarioObject의 Loosen Offset·Loosen Turns로 빠지는 거리와 회전 수를 조절합니다.
프리팹의 작업 대상에는 중복되지 않는 ScenarioObject ID와 Target 종류를 지정합니다. 입력한 Tool Id는 Tools 메뉴 목록, Target Id는 프리팹 작업 대상과 일치해야 합니다. 공구 불필요 목표는 Tool Id를 비워 둘 수 있고, 모든 목표가 공구 불필요라면 Tools도 비워 둘 수 있습니다. ScenarioContent.TryInitialize()가 누락·중복·종류 불일치를 확인합니다. ScriptableObject는 원본 데이터이므로 참가자나 방의 진행 상태를 저장하지 않습니다.
각자 공구 메뉴에서 공구를 선택한 뒤 대상 좌클릭으로 공구 작업 2개와 공구 없는 확인 목표 1개를 함께 진행합니다. SharedScenario가 실제 참가자·거리·순서·수정 번호를 검사하고 NetworkVariable로 진행 상태를 동기화합니다. 선택 공구는 본인의 메뉴에만 표시하고 현재 대상은 노란색, 완료 대상은 초록색이며 방장은 기능 메뉴에서 초기화할 수 있습니다. 대기 복귀 후 다시 시작하면 새 진행 상태로 시작합니다. 에디터의 Smart Training > Content > Prepare Scenario Example로 예시를 준비하며 기존 에셋은 덮어쓰지 않습니다. 역할과 추가 방법은 ScenarioPractice.md를 참고합니다.

1인칭 응시 확대는 모든 콘텐츠에 공통 적용합니다. 모델·영상·시나리오에서 마우스 휠 버튼을 누르면 현재 설정 화각을 기준으로 25% 좁아지고, 놓으면 부드럽게 복귀합니다. UI 위에서는 시작하지 않으며 Esc 메뉴·포커스 상실 시 기본 화각으로 돌아옵니다. 각자의 카메라에만 적용합니다.

### 공통 1인칭 카메라 모듈

`Scripts/Common/Camera/FirstPersonCameraController`가 대상 추적·시점 회전·응시·화각과 시선 기준 이동 방향 변환을 담당합니다. `Bind(Transform, Func<bool>)`로 대상과 조작 허용 조건을 연결하고 `Configure()`로 설정값을 전달합니다. 콘텐츠 타입·RoomPlayer·API·씬 경로는 참조하지 않습니다.
`Scripts/Common/Input/FirstPersonCameraInput`은 Unity Input System 바인딩만 관리합니다. `IFirstPersonCameraInput`을 통해 입력 구현을 교체할 수 있으며 카메라가 입력의 활성화·해제를 책임집니다. 전역 입력 관리자나 콘텐츠별 중복 카메라 로직은 두지 않습니다.
`ContentSceneSession`은 씬 전환 시 카메라 모듈을 생성하고 로컬 플레이어·설정을 연결하며 종료 시 정리합니다. 모델 상호작용에는 모듈이 갱신한 Camera만 전달합니다. 메뉴 입력·씬 로딩·콘텐츠 입력은 각 역할에 남깁니다.

전체 교육과정의 트리와 12개 실행 리소스는 [교육과정 샘플 목록](CourseSamples.md)을 참고합니다.

영상의 재생·일시정지·5초 이동·정지·탐색 슬라이더·개인 음량·자막 설정은 오른쪽 기능 메뉴에서 조절합니다. 메뉴를 닫아도 자막과 공유 재생은 유지됩니다.
